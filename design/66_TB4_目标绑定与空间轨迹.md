# TB4：目标绑定与空间轨迹联动（V0.1）

## 目标

把「用户起始目标」与「定向追踪候选」绑定为一条**身份有依据的单镜头轨迹**，再投影成实验估计地面点，
并与正式 L2、正式轨迹证据隔离。

## 输入

- 起始目标：`anchor = {t, box}`（来自用户框选或起始观测；本轮先用片段内起点帧替代）；
- 候选轨迹集：`tracklets = [{track_id, frames:[{t, box, frame}]}]`（来自定向追踪同镜头连续片段）；
- 相机参数：台账 FOV / 俯角 / 朝向 / 高度 / 经纬度。

## 规则（本轮实现）

1. **绑定**：只接受与 anchor 在时间上重叠、IoU ≥ `bind_iou` 的轨迹，取 IoU 最大者；
   记录 `bind_evidence = {track_id, iou, center_distance, t}`。
2. **逐帧依据**：每帧保存 `iou`、`center_distance_px`、`t`、`frame`，作为身份匹配依据；
   不写“看外观像”这类不可复现说明。
3. **连续性**：帧间 `Δt > max_gap_s` 或 IoU 低于 `track_iou` 且质心位移超过 `max_jump_px` 时**切断**，
   产生新 segment 并记录 `break_reason`，**绝不自动补造缺失轨迹**。
4. **身份冲突**：anchor 时刻若有两条以上轨迹同时达标（IoU 差 < `ambiguity_margin`），
   绑定结果标 `identity_status=ambiguous`，只保留未确认分支，不选“最像”的那个。
5. **状态**：输出 `identity_status ∈ {candidate_unverified, ambiguous}`，
   `spatial_quality=experimental_estimate`，两者独立，不得互相替代。
6. **写入**：`persisted=false`，不写 `target_spatial_observations`，不产生正式 L2。

## 输出

```
{ identity_status, persisted:false, bind_evidence,
  segments: [{track_id, continuity_status, break_reason,
              points:[{t, frame, pixel, ground_point, contact_quality,
                       uncertainty_radius_m, iou, center_distance_px}]}],
  summary:{segments, projected, degraded} }
```

## TB4-3 实施记录

### 时间映射（先解决，避免“轨迹正确、回看跳错时间”）

- `t_abs` 是当天秒数，**不是**播放位置；样本显式给出 `clip_id`、`clip_start_local`、
  `start_of_day_seconds`、`time_basis=clip_start_local`、`time_quality=uncalibrated_osd_ocr`；
- 每个点带 `evidence.day_seconds` 与 `evidence.offset_seconds = day_seconds - start_of_day_seconds`；
- 前端只用 `offset_seconds` 请求关键帧、设置播放器 `currentTime`，绝不把 `t` 当秒数。
- 片段起始时间来自 OSD（未校准），与容器 PTS 是否一致**尚未验证**；接口响应头
  `X-Frame-Time-Semantics: requested-seek-offset-not-verified-pts`、
  `X-Clip-Time-Semantics: container-pts-not-verified-against-osd` 如实暴露这一点。

### 回看链路

1. 点击轨迹点 → `GET /api/v1/cases/{case}/recordings/clips/{clip}/keyframes/image?offset_seconds=`
   返回该偏移的画面（当前实现，JPEG，按请求偏移解码）；
2. 同一面板内 `<video>` 播放 **H.264 代理片段** `GET .../clips/{clip}/proxy-video?start=&duration=`
   （HTTP Range，206）。原因：试点源片是 hevc/yuvj420p，浏览器不能解码，整段原片 615 MB 也不适合起播。
   代理从 `max(0, offset-2)` 起取 20 s、720p/crf26/无音轨、`+faststart`，缓存于 `storage/tb4_proxy`；
   `loadedmetadata` 后 `currentTime = offset - start`，原片仍可通过 `.../video` 读取，不隐藏；
3. 播放位置与目标偏移差 ≤ 1.5 s 时，视频上叠加该帧目标框（超出即隐藏，不假装持续跟踪）。

### 断线与歧义

- 每个 segment 单独成线（`#22d3ee` 虚线）；遇到 `spatial_level != L2-candidate` 或无地面点的帧
  立即 flush，**不跨无效观测连线**，也不把多段有效点收集后统一连接；
- `identity_status=ambiguous` 时 chip 明示“存在接近的竞争轨迹，不自动确认目标分支”；
- 提供 `?variant=ambiguity-probe` 探针（复制同轨迹微移 1 px），响应标 `synthetic=true`，
  仅用于演示歧义呈现，不得用于任何结论。

### 实测

```text
GET /api/v1/target-track/sample                 → 200  candidate_unverified  1 段 31 点
GET /api/v1/target-track/sample?variant=ambiguity-probe → 200  ambiguous  synthetic=true  runner_up=T1-probe
GET .../clip/.../video  (Range: bytes=0-99)     → 206  content-range bytes 0-99/615822280
GET .../clip/.../proxy-video?start=0.40&duration=6 (Range: bytes=0-1023)
                                               → 206  video/mp4  750904 bytes
                                                 x-clip-time-semantics: proxy-h264-reencoded-not-verified-against-osd
                                                 x-proxy-start-seconds: 0.40
GET .../keyframes/image?offset_seconds=2.4      → 200  image/jpeg
```

### 边界（必须保留）

- 身份：`candidate_unverified`，anchor 取自 T1 自身一帧，`iou=1.0` 只证明绑定算法可用，
  **不构成身份确认**；
- 空间：`experimental_estimate`，未经标定审核、无独立地理真值，不写 `target_spatial_observations`；
- 回看：按容器 PTS 跳转，与 OSD 时间的一致性未核验，因此不称为“精确逐帧回放”；
- 代理：重编码副本（720p、crf 26、删除音轨），只用于人眼核对来源，不作为画质或检测输入证据。

## 与原始需求的差距（TB4-4 起）

- anchor 来源：本轮 anchor 是样本 JSON 里的固定框（取自 T1 自身一帧），不是用户在截图上框选，
  因此绑定结果只证明算法可用，界面仍写“候选目标｜身份未确认”。
- tracklets 来源：本轮用 OpenCV MOG2 + IoU/质心关联在片段内重新检测，并非读取
  tracking_candidates（定向追踪产物）；换成库中候选后，才叫“从现有定向追踪候选里选”。
- 断线演示：规则与单测已有，但真实样本绑定后是单段，页面上还没出现过断成两段的实例。
