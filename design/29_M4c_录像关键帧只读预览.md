# M4c 第一阶段：只读录像关键帧与候选观测

## 目标

主系统的「录像资源」通过 M3 的 RecordingSource / RecordingClip 接线，只读取得少量指定偏移的画面。**只通过 overlay_identity.grab_evidence_frame 取帧**，不实现新一套 ffmpeg；过滤花屏、灰帧后返回可用情况、画质及可选 D-FINE 检测建议。

此阶段不生成 Tracklet，不写录像，不将视频目标自动绑定身份，不向 TrajNexa_Map 写任何轨迹。下一步才引入单镜头局部连续跟踪、关键帧综合评分、人工审核及关联证据。

## API 与来源

`POST /api/v1/cases/{case_id}/recordings/clips/{clip_id}/keyframes/preview`

~~~json
{"authorized":true,"offsets_seconds":[0.5,2,8],"include_detection":false}
~~~

`GET /api/v1/cases/{case_id}/recordings/clips/{clip_id}/keyframes/image?offset_seconds=2&authorized=true` 返回短时取帧得到的 JPEG，不保存至磁盘，Cache-Control 私有且 no-store。

只允许已由案件添加的录像目录，并检查 `clip.source_id` 所属 `case_id`、磁盘目录、文件大小和 mtime_ns 与扫描记录一致。文件改变必须先重新扫描；镜头 UUID、时间起点均作为未经当前观测核对的候选。`requested_offset_seconds` 是希望跳转的偏移，**不是经解码 PTS 校验的真实帧时间**。`start_time_candidate` 来自旧 OCR / 文件名，不自动推断绝对时间或终止时间。

每次最多采样 6 帧；检测可选、只读，未配置真实权重时明确 503，不生成模拟框。无效帧标为 frame_unavailable，绝不等于目标不存在。

## 使用与限制

在受控本地 `.env` 开启 `M4A_ENABLED=true` 和 `M4C_ENABLED=true`。若要开启模型检测，需另按 M4b 文档配置本地 D-FINE ONNX 和 SHA-256，使用 `compose.m4b.yaml`。

当前没有正式的登录认证与角色隔离；authorized 参数仅为人工声明，不能视为真正授权。生产部署前必须加入任务范围权限与审计，禁止公网开放。

### 测试

CI 新增 `tests/test_m4c_keyframes.py` 和 `tests/test_m4c_api.py`，用替身模拟共享取帧器，验证案件隔离、无效帧、原录像变化、错误码、JPEG、未确认时间及无 Tracklet。它们**不是**真实现场录像、PTS 精度与 D-FINE 实测验收。

## 后续

M4c 第二阶段：局部检测序列、单镜头 Tracklet 和关键帧筛选；每段局部关联必须可撤销，不能以此证明跨摄像头同一身份。M5 地图轨迹须依赖经核实的时空观测，不能把视频帧内坐标直接当作 GIS 经纬度。
