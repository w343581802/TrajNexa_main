## 0. 本版确认的核心决策

1. **产品目标包含两个并行但不同的成果**：① 在证据允许的范围内自动还原**最有可能属于用户指定目标**的可核查轨迹；② 沿候选轨迹主动寻找**清晰、可核验的目标人脸、车辆车牌或其他高价值细节**。任务可同时追求两者，也可按授权目的单独启用。
2. **清晰证据主动发现不是身份自动确认**：找到一帧清晰脸部或车牌，只说明存在可用于授权人工核验的原始画面。人脸外观比较、车牌文字读取、个人身份确认属于不同决策；证据不足时不承诺获取结果。
3. **中近距离识别，远距离连续跟踪**：远距离允许匿名移动物体轨迹；达到可辨质量时，与用户目标锚点进行轨迹级多视角比对；可信 Tracklet 支持向前回溯、向后延伸。画质变差不自动抹去已有轨迹，但发生换人风险时必须降级为候选或断轨。
4. **同位置多个摄像头不默认全部分析**：先判断位置/安装点是否值得搜索，再根据任务目标、相机朝向、理论或实测视野、历史画质和录像可用性，选择**当前最有价值的一个或少数通道**；其余镜头作为备用或验证镜头。不能因为机位相同就把方向互补的有效镜头全部排除。
5. **轨迹价值与清晰画面价值共同驱动调度**：最容易看到目标移动轨迹的镜头，不一定是最容易拍到人脸或车牌的镜头；调度必须按照当下任务状态和目标方向改变优先级。
6. **普通场景小模型优先**：D-FINE + ByteTrack 保持当前实验基线，OSNet x0.25 用于有质量保障的人员外观排序。Qwen3-VL 仅在关键且有足够可见信息的歧义候选上按需调用，不逐帧运行，也不允许强制续接 Track ID。
7. **身份、轨迹和证据分离**：`Target`、`Tracklet`、`IdentityHypothesis`、`EvidenceAsset` 是独立实体。仅因时空合理或外观高分，不将疑似轨迹写成已确认身份；未核实的新观测不得污染目标原始参考锚点。
8. **不完整资料不是排除证据**：地图覆盖、路网、摄像头视野、时间校准和历史录像可能缺失。缺少信息时保留 `unknown`，不以虚假的精度排除合理候选。
9. **以授权范围为硬边界**：摄像头、录像时段、人员数据访问与关键画面调取均受任务授权、审批、最小化留存与审计控制。无关主体不因同画面出现就自动建立长期档案。

## 1. 产品目标：轨迹还原与关键证据发现

### 1.1 目标一：最有证据支持的轨迹

用户上传指定人员或车辆的参考照片、视频片段或人工核实观测。系统在授权范围内反复执行：候选发现 → 视觉比较 → 时间/空间审查 → 摄像头选择 → 录像分析 → 更新候选证据 → 必要时向前回溯或向后延伸。

输出应包含：原始录像对应片段、观测时间、摄像头/通道、临时轨迹、关联理由、竞争候选、人工核验状态、空间范围、时间误差与可能盲区。不得以一条无断点折线掩盖没有录像支持的间隔。

### 1.2 目标二：寻找清晰可核验的关键画面

沿目标轨迹或其高价值候选路径，优先搜索可能获得下列证据的摄像头与时间窗：

- **人员任务**：清晰的人脸可见画面（优先正面、近距离、少遮挡、曝光和清晰度良好的原始帧）；衣着、背包、鞋子、携带物品等补充特征。
- **车辆任务**：牌照区域清晰、文字具有可读性的原始帧；车身颜色、形态、显著贴纸或尾箱等辅助特征。车牌是否能够识别取决于拍摄距离、角度、快门、分辨率、灯光以及是否实际挂有牌照。
- **人车关系任务**：人员与车辆同框、骑乘/上下车的连续可核验片段。只有关系已确认或保留明确候选标记时，才可借车辆继续寻找目标人员的线索；**找到了车辆不等于找到了人员**。

任务可以返回：`found_reviewable_face_frame`、`found_reviewable_plate_frame`、`only_partial_visual_evidence`、`not_found_in_available_video`、`insufficient_quality`、`video_unavailable` 等状态。任何“清晰”阈值须经过人工样本标定，不能只凭模型自述质量。

### 1.3 任务模式（可组合）

| 模式 | 主要目标 | 搜索侧重点 | 可结束条件（由任务策略与人工授权决定） |
|---|---|---|---|
| `trajectory` | 重建目标候选轨迹 | 连续覆盖、出入画方向、跨镜头可达性 | 到达授权终点/时间、无继续证据、人工结束 |
| `face_evidence` | 寻找清晰目标脸部画面 | 正面或斜正面、较大脸部、少遮挡、原始画质 | 已找到足以人工复核的原始画面或范围耗尽 |
| `plate_evidence` | 寻找清晰牌照画面 | 车头/车尾与牌照位置、拍摄角度和车辆速度 | 已找到足以人工复核的原始画面或范围耗尽 |
| `combined` | 轨迹与关键证据并行 | 根据已有证据动态改变镜头排序 | 达到指定的多项成果、人工结束或资源/范围耗尽 |

**重要区别**：对用户目标的外观相似性与“画面中的脸/牌照是否清晰”是两条相互独立的判断链。清晰的无关人员或无关车牌不得冒充任务成果。

## 3. 目标与轨迹的证据结构

### 3.1 四类对象及其职责

- `Target`：用户指定的人员或车辆、初始参考图和授权上下文，永久保留最初目标锚点（在规定留存期内）。
- `Tracklet`：某台摄像头某时段的临时观测序列；普通运动跟踪不需要每帧识别身份。轨迹号不等于目标身份。
- `IdentityHypothesis`：某段 Tracklet 可能对应某个 Target 的*可撤销假设*；包含支持证据、冲突证据、时间/空间不确定性以及 `candidate/ambiguous/rejected/human_confirmed` 等状态。
- `EvidenceAsset`：视频原件、关键帧、时间戳、源通道、原始像素坐标及人工复核信息。检测框/模型描述是衍生分析，不覆盖原件。

同一 Target 可以同时保留数条未决候选；同一条 Tracklet 不能因为两个候选都打分高就自动确认属于两人。

### 3.2 中近距离匹配与轨迹延伸

1. 远距候选保持匿名跟踪（可有 `person/two_wheeler/unknown_moving_object` 的不确定分类）；但“匿名”不意味着任意低质量运动伪影都要创建长期轨迹。
2. 目标达到有质量保障的中近距离帧时，按时间分层取样、保留不同视角，使用 OSNet 及可见属性与用户 Target 参考比较。
3. 匹配输出是**候选排序和证据差异**，不是经过校准的身份概率。只有时空和竞争条件允许，才把候选 Tracklet 连接到目标假设。
4. 可信的**同一条连续 Tracklet 内**，可以由中近距离观测向前回溯远处进画路径、向后延伸远离路径；出现明显跟踪身份交接风险时，应保留断点。
5. 正反向新证据都可以更新对旧轨迹的评价，但不能抹掉原判断和原始证据。

### 3.3 多视角特征与可见性

目标特征不是一个无差别平均向量；保存时间分散的原始向量、可辨方向 `front/back/left/right/oblique/unknown`、视角判断可信度和每项可见属性的状态。

**摄像头朝向 ≠ 人体朝向**。人物运动方向仅能辅助估计拍摄的是正面或背面，不能代替姿态观察。视角不匹配时，应降低单帧外观排除的力度，而不是把看不到的面认作“特征不存在”。目标转身、脱衣、上下车等事件也可能改变可观察特征；动态特征必须带时间有效范围和人工核验状态。

## 4. 摄像头选择：先选地点，再选最有利的镜头

### 4.1 为什么不能简单按最近摄像头排序

同一个路口或安装点可能同时有：

- 面向道路来车方向的车道镜头：更容易看到车牌正面，但对人员可能只拍到远景。
- 面向人行通道的镜头：更容易看到迎面而来的人员脸部。
- 俯拍全景镜头：更擅长连续运动轨迹与分流方向，但人脸、牌照像素可能不足。
- 背向出口或监控另一侧的镜头：在某些行进方向上是优质备用镜头，在另一些方向上完全无用。

同一 `site_uuid` 的多个 `camera_uuid` 必须被识别为“同点位多通道”，而不是重复地点；**一次任务优先分析最有价值的通道，并按需要选择互补通道**。

### 4.2 两级选择

**第一级：地点/路口（Site）优先级**。根据上一条已核实轨迹的最后时间、可达区域、出入画方向、人员或车辆可能路径、任务时间窗、路网与空间校准质量，生成需要搜索的地点集合。

**第二级：同点位通道（Camera/Channel）优先级**。对同一地点的镜头比较：是否覆盖目标可能通过的区域、面向目标行进方向时的可见正背面、预计目标像素高度或牌照可见角度、遮挡、照度、录像可用性、时钟质量和处理成本。

**搜索策略**：优先运行最有利的 1 个镜头或少数互补镜头；其余保持 `deferred`。若未得到可用证据、发现轨迹分叉、首选镜头仅有背面、牌照不可见或视频断档，再升级检索其他镜头。不能“只扫首选”导致系统悄悄漏掉唯一拍清脸/牌的另一通道。

### 4.3 任务驱动的择优指标

| 指标 | 轨迹任务 | 人脸证据任务 | 车牌证据任务 |
|---|---|---|---|
| 目标可能经过该区域 | 强约束/强排序 | 强约束/强排序 | 强约束/强排序 |
| 目标连续可见时间 | 优先 | 有帮助 | 有帮助 |
| 预计人员脸部朝向、可见面 | 辅助 | **高优先级** | 非主要 |
| 预计牌照可见面、安装角度 | 辅助 | 非主要 | **高优先级** |
| 目标在画面中的有效尺寸 | 足以连续跟踪即可 | 脸部需足以人工核验 | 牌照字符需足以人工核验 |
| 运动模糊、夜间补光与曝光 | 中高 | 高 | 高，反光过曝特别重要 |
| 遮挡、FOV、PTZ 历史版本 | 高 | 高 | 高 |
| 录像可用时间、时钟误差 | 必需核查 | 必需核查 | 必需核查 |
| 计算开销与重复覆盖 | 优化项 | 优化项 | 优化项 |

**质量不同则角色不同**：一台镜头负责“确认目标经过路口”，另一台负责“寻找清晰脸/车牌”，即使安装点相同也不是无效重复。

### 4.4 通道能力画像（由 TrajNexa_Map 提供元数据，主系统计算任务价值）

优先利用 `site_uuid`、`camera_uuid`、相机位置、朝向、安装高度、镜头焦距/视角、理论和已校准 FOV、遮挡、车道人行区域、PTZ 姿态历史、标定有效时段、数据质量、`spatial_revision`。

**由 TrajNexa 主系统补充、验证与维护的内容**：录像实际分辨率、帧率、码率、夜视或红外、清晰关键帧历史观测、脸部/牌照局部可辨程度分布、录像覆盖时段、设备时钟偏差估计、推理成功/失败统计、平均分析成本等。以上不是要求 Map 去运行模型。

未知的镜头质量保持 `null/unknown`，不能假设它差就永久排除。可以安排小规模探测片段校准其任务价值。

### 4.5 一个地点四通道的示例（仅说明策略，非真实设备事实）

同一路口有四台摄像头，目标从西向东步行，当前任务优先寻找清晰人脸：

| 通道 | 典型拍摄内容 | 本次处理决定 | 原因 |
|---|---|---|---|
| A：俯拍全景 | 行人经过和分流方向 | 先做低成本路径验证 | 容易连轨，但脸部通常较小 |
| B：东向西拍摄人行道 | 朝镜头迎面走来的人员 | **优先精查** | 对西→东行人可能获得正面清晰画面 |
| C：西向东拍摄人行道 | 行人背面 | `deferred` | 可用于侧后方衣着或回溯，但未必有正脸 |
| D：机动车牌照抓拍 | 车道车头/车尾 | 暂不分析 | 任务是步行人员脸部，不是车辆牌照 |

若目标随后骑车转入车道，或 B 的录像恰好不可用，则 C/D 可能变成必要候选。**同位置择优是动态决策，不是永久关闭某些镜头。**

### 4.6 排序逻辑与降级

先做**硬约束**：授权、录像是否存在、时间段是否可访问；无权限禁止调用，录像不可用记录原因。对其余满足条件的镜头采用任务相关的排序，不把预设权重当成校准概率。

一个可测的启发式结构：

```text
site_candidates = spatial_temporal_candidates(last_evidence, travel_window)
for site in site_candidates:
    channels = cameras_with_same_site_uuid(site)
    for camera in channels:
        if not authorized(camera, task) or not video_available(camera, window):
            record_unavailable(camera)
            continue
        route_value  = estimated_target_coverage(camera, movement, time_uncertainty)
        detail_value = expected_face_or_plate_opportunity(camera, task.goal, direction)
        quality      = observed_image_quality(camera, time_of_day)
        diversity    = marginal_coverage_not_already_examined(camera)
        cost         = estimated_decode_and_inference_cost(camera, window)
        priority     = task_dependent_rank(route_value, detail_value,
                                           quality, diversity, cost, uncertainty)
    analyze(best_supported_channels(site), bounded_time_windows)
    if evidence_insufficient_or_conflicting:
        expand_to_complementary_channels(site)
```

**关键约束**：

- `expected_face_or_plate_opportunity` 只是“可能拍清”的先验，不是已找到目标/人脸/牌照。
- 既要利用高收益镜头，也要保留少量对未知镜头或替代路线的探索预算，防止历史经验导致系统性漏检。
- 时间/空间不确定性大的任务使用更宽的候选窗口，不作刚性“不可能”否决。
- 摄像头与 PTZ 在历史录像时的朝向优先于当前台账朝向；没有历史记录则只能估计。
- 不同任务可重排相机优先级，且用户可查看“为何选择/暂缓/跳过某镜头”。

## 5. 清晰人脸与车牌画面的发现机制

### 5.1 两阶段发现，不将“清晰目标”混入初始识别

**第一阶段：沿可信或高价值候选轨迹定位画面。** 先用检测、跟踪、OSNet、时空条件确定“此片段可能包含目标”；不应扫描全城所有镜头来泛化寻找清晰面孔。

**第二阶段：仅在目标候选相关的帧段内寻找最佳细节。** 对人员检测脸部区域、对车辆检测牌照区域；计算原始有效像素、焦点清晰度、可见角度、遮挡、过曝/欠曝、运动模糊等质量信号。把能否人工辨认作为离线标签，而不凭模型打分直接判断“清晰”。

候选关键帧按时间分散取样，除高分单帧外，还保留前后连续短视频，以确认它确实属于同一条目标轨迹。优先保存原始码流中的最佳帧，不能把已经降采样的推理图放大后冒充原始清晰画面。

### 5.2 人脸关键帧

- 本阶段的任务是**找到目标候选对应的可人工核验脸部画面**，不是自动将画面中的脸与公民身份信息匹配。
- 建议输出 `face_visible`、`face_reviewable`、`face_quality_reasons`、`face_crop_original_ref`，分别记录是否可见、是否适合人工复核以及不足原因。
- 人脸朝向、尺寸、遮挡、逆光、反光和运动模糊共同影响判断；正面不等于一定清晰。
- 若只能获得背面或低像素脸部，返回 `insufficient_quality`，可继续检索更有利镜头。

### 5.3 车牌关键帧

- 车辆可能没有可辨牌照或只有车头/车尾某侧悬挂牌照；摄像头和行驶方向决定可见性。
- 清晰牌照候选应保留原始画面及字符可读性评价；牌照 OCR 若未来启用，要记录多个帧的读数分歧、字符模糊位置与人工核验结果，不能将单帧 OCR 自信度当事实。
- 两轮车车型细分（`motorcycle/electric_two_wheeler/bicycle/unknown`）与车牌是否可见分开处理；车辆类别不决定是否一定有号牌。
- 禁止生成式补全被遮挡、反光或模糊到不可读的字符。增强后的图片如存在必须标记为辅助显示，原始帧始终是依据。

### 5.4 关键帧的证据价值与目标关联

采用两项独立评价：`visual_quality`（画面是否清晰）和 `target_link_evidence`（该帧中的对象是否可能为指定目标）。只有两者都满足经审查的要求，才可报告“发现与目标相关的高价值清晰画面”；否则只能保留为“清晰画面但目标归属未确认”。

## 6. 大模型的触发方式

沿用“**小模型检测和跟踪、时空缩小范围、大模型按需消歧**”。

允许触发的典型情形：两个时空合理的候选出现相似衣着而无法区分；人员与两轮车关系中的骑乘/推车/并行歧义；关键画面中某件可见随身物品是否相符。一次分析使用少量高质量、时间不同的目标裁剪及必要上下文图。

不得触发或不应寄望解决的情形：原画面只有不可辨像素；视频源缺失；时间空间信息已可靠排除；为了寻找清晰脸/牌对每个无关轨迹逐一调用 VLM；让 VLM 猜测不存在的脸部或牌照细节。

调度模块记录每次调用的 `reason`、输入帧引用、模型/权重版本、耗时、输出、可核验价值，并支持资源预算、去重缓存及失败后返回 `unknown`。

## 8. 任务执行循环与停止规则

```text
指定目标与授权范围
       ↓
初始化原始锚点 / 已确认观测 / 任务模式
       ↓
以中近距画面建立或验证候选 Tracklet
       ↓
同一 Tracklet 内可信地双向追溯与延伸
       ↓
结合时间、可达区域和任务目标选候选 Site
       ↓
每个 Site 按轨迹价值 / 人脸或车牌机会选少量 Channel
       ↓
逐级分析：低成本扫窗 → Tracklet → 质量/身份候选核查
       ↓
提取与任务相关的清晰原始关键帧
       ↓
证据充分？ ─── 是 → 记录成果，按任务目标继续或结束
       │
       否
       ↓
回查互补镜头 / 扩大合法时间窗 / 保留候选分支 / 人工审查
       ↓
资源预算、授权范围或有效信息耗尽 → 暂停并说明未知
```

**完成/暂停的原则**：找到脸或牌不意味着轨迹已完整；轨迹无法继续也不意味着没有清晰关键画面。多目标任务需分别标记每项目标的状态。审批人可设定优先级、最大镜头数、处理时长、重试次数与必须人工核验的阶段。

## 9. 测试优先路线（当前应执行的范围）

| 阶段 | 工作 | 交付 | 本阶段不做 |
|---|---|---|---|
| **S4-0** | 原始录像时间轴、相机/通道 ID、参考锚点和 GT 对齐 | 可复现输入清单；真实连续人员 GT | 不复用已知偏移不明 GT 得出成绩 |
| **S4-1** | 单镜头“远→近→远”匿名跟踪、近距比对、同 Tracklet 回溯 | `tracks / hypotheses / evidence`，正确覆盖和错误换人报告 | 不新增检测器或跟踪器 |
| **S4-2** | 单/多视角模板与可见性对照 | 单向量 vs 多视角逐帧/轨迹模板报告 | 不以平均余弦提高代替任务成功率 |
| **S4-3** | 单地点多通道的任务驱动选择对照 | 选择记录、跳过/回查原因、资源消耗 | 不默认全镜头全录像推理 |
| **S4-4** | 在已关联目标候选内提取清晰脸部/车牌原始帧 | 人工核验的关键帧及失败原因 | 不自动认定真实身份、不生成不存在的细节 |
| **S4-5** | 两至三摄像头的多轮候选扩展与反向审查 | 可撤销的轨迹证据图和时间线 | 不把多摄像头路径补线当事实 |

### 9.1 最小真实测试素材要求

1. **单镜头人员**：目标从远到近再远离；中近距离有可比对画面；至少包含相似衣着干扰人员。
2. **单地点多通道**：同一 `site_uuid` 至少两个不同方向的通道，录像时段重叠；至少一次目标经过、至少一个可产生更清晰画面的互补镜头。缺少此类素材则择优策略只能做规则单测，不得声称真实通过。
3. **跨镜头场景**：两至三台有已知时间关系和合法录像的镜头；既有正确接续，也有“相似但不是”的负例，以及录像缺失/时间偏差案例。
4. **脸/牌证据场景**：人工标注哪些原始帧确实适合核验，哪些虽然清晰但不是目标；允许“没有任何可用清晰脸/牌”的真实负样本。
5. **数据隔离**：人工真值与算法输出分离；录像与目标锚点、标注帧的绝对时间和帧号一一对应；同机位相邻帧不能同时泄漏到调参集和最终验收集。

### 9.2 建议的任务级指标

| 指标 | 衡量什么 | 重点防范 |
|---|---|---|
| 指定目标候选召回 | 真目标可辨时是否进入候选 Top-K | 因质量门槛静默过滤真目标 |
| 错误目标关联 | 把其他人或车辆误关联为指定目标的次数 | 错误换人后整段轨迹被污染 |
| 可信轨迹覆盖 | GT 真实经过时间里，被正确 Tracklet 支持的比例 | 轨迹越长越好但跟错目标 |
| 远→近回溯正确性 | 识别点前同 Tracklet 的可信历史是否属于本人 | 在反向回溯时跨错误 ID Switch |
| 关键画面发现率 | 真正存在可人工核验帧的案例中能找出多少 | 输出清晰但非目标的脸/车牌 |
| 关键画面 Top-K 命中 | 首批提交审核的候选里是否有有效清晰帧 | 全量找到了但优先级很差 |
| 相机择优覆盖损失 | 相比同窗全镜头参考，择优策略漏掉多少可用关键证据 | 为省算力漏掉唯一最佳镜头 |
| 相机分析成本节省 | 解码帧数、推理次数、总耗时、VLM 调用数减少量 | 只报省时不报漏检 |
| 不确定性与拒绝质量 | 无法判定时是否正确保留未知、录像不可用 | 把未观察到当不存在 |
| 审计可追溯率 | 目标、镜头选择、关键帧、模型、时间、人工审核是否能回查 | 结果不可解释、无法回滚 |

验收以完整标注的真实正负样本为基础，**不预设虚构的准确率阈值**。同地点多镜头择优必须同时报告“省了多少分析工作”与“因此遗漏了多少本可找到的目标画面”；仅报告吞吐量或镜头数量下降不构成通过。

## 10. 近期开发决策与待补数据

### 10.1 本轮可立即做

- 确认 `Target/Tracklet/IdentityHypothesis/EvidenceAsset` 的离线 JSON 约定。
- 冻结并校验单镜头真实 GT、绝对视频秒和源帧映射；优先完成“中近距匹配 → 向前回溯 → 远离延伸”完整实例。
- 盘点测试范围内 `site_uuid` 与 `camera_uuid` 的一对多关系和相机方向，制作一个同位置 2～4 通道的“全镜头基准 vs 择优”实验。
- 在已有候选轨迹上做关键帧**质量排序**试验，先人工核验，确认能否找到原始清晰脸/牌画面；没有真实样本则如实标记未验。

### 10.2 明确暂缓

- 20×20 人员或车辆身份识别专项训练、YOLO 横向模型竞赛、继续更换 MOT 算法。
- 困难密集场景强制续接、未核实候选自动扩充目标档案。
- VLM 全量逐帧分析、模型生成/补全缺失的人脸与牌照信息。
- 未通过测试即开发完整跨镜头 UI、无界定预算的全网录像搜索。

### 10.3 尚需实际采集或校验的信息

1. 同一安装点多通道的稳定 ID、实际方向、可用录像时间与分辨率；必要时区分安装位置 `site_uuid` 和通道 `camera_uuid`。
2. 代表性镜头的历史 PTZ/FOV、遮挡与昼夜画面差异；没有则标 `unknown`。
3. 可取得清晰脸/牌原始帧的真实片段及**人工核验标签**；“某台摄像头理论上拍正面”不等于确实拍清。
4. 多通道之间的时间偏差及视频解码 PTS 锚定；不能复用已知时间轴不匹配的旧真值直接验收。
5. 所有样本的授权范围、模型版本、数据来源与测试切分。

## 11. 与既有规划的关系

- **保留《总体规划文档 V1.0》的主系统/Map 双系统分工**：Map 维护空间信息和版本，主系统依据任务做相机择优与录像研判；Map 不是业务展示地图。
- **保留 design/44 的实测结论**：D-FINE + ByteTrack 基线、OSNet 质量门槛、可疑轨迹拒绝强关联、FastTracker 首轮不通过、下车解除未验证等均不因新规划自动改变。
- **调整实施焦点**：从反复优化单机位极小目标检测，转向用户目标的中近距离识别、可信单轨迹回溯/延伸、多视角特征、同位置多镜头择优和清晰证据发现。
- **新增清晰人脸/车牌发现作为明确的产品成果**，但始终区分画面质量、目标归属与身份确认；优先给出原始、可复核的证据。
- **后续回写建议**：如本规划经确认，将第 0 节目标原则同步至总体规划与 design/44 的后续修订；旧文档中的实验历史与未通过结论原样保留，不覆盖。

### 最终产品定义（建议纳入总体规划）

> **TrajNexa 是在合法授权监控资源内，以用户指定人员或车辆为起点的连续跨镜头时空研判系统。系统通过中近距离目标比对、远距匿名运动跟踪、多视角证据和时间空间约束，自动寻找最有证据支持的候选轨迹，并沿轨迹主动发现可供人工核验的清晰人脸、车牌或其他关键原始画面。对同一地点的多个摄像头，系统根据轨迹覆盖、目标方向和关键证据可见机会动态选择最有利的一个或少数通道，在证据不足时回查互补镜头，避免无意义的全通道重复研判。所有结果保留原始来源、证据冲突与不确定性，不承诺唯一身份、完整轨迹或必然取得清晰画面。**
