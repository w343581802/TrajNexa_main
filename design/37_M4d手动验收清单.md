# 37｜M4d 手动验收准备与判定

## 已完成的自动化范围
- M4a–M4d 后端合约测试与 Vue/TypeScript 构建（GitHub Actions）。
- 关键帧请求与 VLM 请求分别采用过期响应隔离；切换案件、录像、帧或图片失败时清理旧属性。
- 本地 HTTP mock server 测试覆盖 JPEG data URL → OpenAI-compatible chat/completions → 严格属性 JSON。
- 模型服务默认关闭、限制 loopback、超时上限 120 秒、一次只允许一个请求；模型异常不生成有效候选。

## 手动验收前准备
1. 本地启动 TrajNexa Demo 后端和前端，准备一个已登记到案件并已扫描的短视频。
2. 在与后端相同的网络命名空间启动兼容 OpenAI chat/completions 的**视觉模型**服务，确认支持 JPEG data URL；容器内 localhost 不等于宿主机 localhost。
3. 在后端环境变量设置 `M4D_ENABLED=true`、`M4D_MODEL=<实际模型名>`，可选 `M4D_BASE_URL=http://127.0.0.1:11434/v1`、`M4D_TIMEOUT_SECONDS=30`；重启后端。
4. 在录像关键帧面板选择 1–6 个偏移，读取关键帧，选择一帧点击“分析当前帧属性”。

## 通过标准
- 可见属性返回 clothing_upper / clothing_lower / carried_item / visible_motion 中的有限候选，标明未核实；看不清时应为空、unknown、uncertain 或明确模型失败，而非身份结论。
- 关键帧切换、案件切换、图片失败不会残留前一帧候选。
- 关闭 M4D_ENABLED 返回 503，模型服务离线/超时显示失败，不产生伪造属性。
- 不自动写入案件观测、身份绑定或轨迹；录像文件保持原样。
- 时间偏移仅为请求 seek，不能当成已核实的精确帧时间。

## 尚未自动验证
真实录像编解码、真实视觉模型对光照/遮挡/低分辨率的表现、实际部署网络可达性和端到端操作体验。必须在目标机器上人工验证；通过前不要合并 Draft PR。
