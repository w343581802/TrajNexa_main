# 35 添加要素：自动框选与关键特征（Demo 口径，M4d）

> 依据 [26 号文档的「约束 0」](26_能力地图与复用契约.md)：当前交付物是**技术验证 Demo**。
> 本文记录为演示而做的交互与接口调整，结论不能当生产结论用。

## 1. 要解决的问题

演示「添加要素」时，人工只能拖框，系统看起来什么都没识别：

- 选完图没有任何反馈，看不出系统「看到」了目标；
- 弹窗里要求勾选「本案件素材已获授权处理」、还要求选取依据≥8 字，演示时纯属挡路；
- 只有一个模型可选，没法现场对比效果；
- 框选结束后没有「关键特征」，看不出这一框的观察价值。

## 2. 现在的交互

1. 选中一张案件截图 → **自动**跑一次识别（默认 Qwen3-VL），画面上直接出现候选框。
2. 顶部两个引擎 chip：`Qwen3-VL` / `D-FINE`，点一下换引擎重跑，同一张图直接对比。
3. **点候选框 = 选中**：框变实线，类别自动带上（person / vehicle / other），
   并立刻拉取「关键特征」：框像素范围、亮度、清晰度、主色占比、画质告警、外观短语。
4. 手画拖框仍然可用（老路保留），松手同样自动出关键特征。
5. 保存时不再要求授权勾选与 8 字依据；依据留空会按引擎自动生成一句话。
6. 模型产出始终是「候选 / 建议」：不写库、不改原图、不确认身份或地理位置，
   只有点「保存为目标要素」才落一条待人工复核的观测。

## 3. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/media/{id}/detect` | 统一识别入口，`engine=dfine\|qwen3vl`，返回 `candidates[]`、`engine`、`model_family`、`image_size`、`elapsed_seconds` |
| POST | `/api/v1/media/{id}/roi-features` | 选中框的关键特征：确定性统计 + 视觉模型外观短语（模型失败只降级，不整单失败） |
| POST | `/api/v1/media/{id}/detections/preview` | 旧 D-FINE 路径，保留兼容；内部与 `/detect?engine=dfine` 同一实现 |

两个引擎返回同一套 `candidates` 结构：

```json
{"proposal_index": 0, "object_class": "vehicle", "detector_label": "car",
 "confidence": 0.47, "bbox_normalized": [0.0087, 0.5247, 0.6548, 0.9855],
 "status": "unverified_detection_proposal"}
```

- `confidence`：D-FINE 给分数；Qwen3-VL 不评分，固定 `null`（界面显示「未评分建议」）。
- `status`：`unverified_detection_proposal`（检测器）/ `unverified_vlm_proposal`（视觉模型）。
- 坐标统一 0..1 归一化、左上右下，前端直接乘百分比画框。

`roi-features` 的模型部分是**加分项**：Ollama 不可用时返回
`appearance.semantic_status="unavailable"`，画质与主色照常返回。

## 4. 两个引擎的实测（同一张 1280×960 监控截图，CPU）

| 引擎 | 模型 | 候选数 | 服务端耗时 | 备注 |
| --- | --- | --- | --- | --- |
| D-FINE | `dfine_n_coco` ONNX（14.6 MB） | 7 | **0.61 s** | 分数 0.36–0.47，框更贴合目标边界 |
| Qwen3-VL | `qwen3-vl:2b-instruct`（Ollama） | 2 | **2.05 s** | 带中文语义标签（「轿车」），框偏粗、召回低 |

对比结论（Demo 层面）：**D-FINE 快且框准，Qwen3-VL 能说出「是什么」但慢、框粗**。
两条通道都给候选，人工点选后才成为观测——这正好是演示想要的分工。

## 5. 模型适配时踩到的四个坑

1. **thinking 变体没有输出**：`qwen3-vl:2b` 会把 token 全花在 `thinking` 上，
   `content` 为空（实测 `eval_count≈15000`、137 s、`done_reason=length`）。
   接口现在返回稳定错误码 `m4d-model-thinking-only`，提示换 `*-instruct`。
2. **必须限制生成长度**：不设 `num_predict` 时 2B 模型会陷入重复字段，一分钟都停不下来；
   现在固定 `num_predict=400` + `repeat_penalty=1.1`，稳定停在完整 JSON 上（约 1–2 s）。
3. **`format:"json"` 会把 box 弄丢**：语法约束下模型常常只输出 `label/category` 就收尾；
   因此关掉语法约束，改成「容错解析」：容忍 ```json 围栏、容忍一句话、容忍自造字段。
4. **D-FINE 有两种 ONNX 契约**：官方导出是 `images + orig_target_sizes → labels/boxes/scores`，
   HuggingFace/onnx-community 导出是 `pixel_values → logits + pred_boxes`
   （cx,cy,w,h 归一化）。`m4_detection` 现在按输入名自动判别并在内部换算成同一套三件套。

另外两个模型都会对同一目标给多个重叠框，因此两侧都加了去重：
D-FINE 用「IoU + 中心距离 + 面积比」的类无关 NMS，视觉模型按同样规则丢重复框。

## 6. 已知限制（登记，不在 Demo 阶段修）

- 框的精度只有像素级近似：D-FINE 只映射 COCO 的 person/bicycle/car/motorcycle/bus/truck 六类，
  其余类别（三轮车、摊位等）不会出框；Qwen3-VL 召回明显更低。
- `object_class` 只有 person / vehicle / other；标签是中文短语，不做实体链接。
- 外观短语来自 2B 模型，可能自造字段、可能只给颜色词，**只能当提示**，不能当证据。
- 一次只保存一个框；多目标要逐个点选保存。
- 没有做识别结果缓存：每次切引擎/重开图片都会重新推理（D-FINE 0.6 s 可接受，VLM 2 s 也够演示）。
- 两个引擎都在 CPU 上跑；并发靠进程内信号量（D-FINE 429 忙），不是队列。

## 7. 验证

- 后端：`tests/test_m4a_observations.py`、`test_m4b_preview_api.py`、`test_m4b_detection.py`、
  `test_m4d_detect.py` 共 **38 passed**（授权不再是闸门、D-FINE 两种契约、去重、模型降级都有用例）。
  全量套件仍为 **4 failed**（`test_m1c`/`test_m1d`），与 [33 号文档](33_M3代码审核与修复记录.md) 记录的既有失败一致，非本次改动引入。
- 前端：`npx vue-tsc --noEmit` 通过。
- HTTP 冒烟：同一张截图 `engine=dfine` 7 框 / 0.61 s，`engine=qwen3vl` 2 框 / 2.05 s。

## 8. 复跑

```powershell
# 1) 权重与模型（一次性）
curl.exe -L --fail -o models/dfine.onnx `
  "https://huggingface.co/onnx-community/dfine_n_coco-ONNX/resolve/main/onnx/model.onnx"
$env:OLLAMA_MODELS='G:\tools\ollama\models'
& 'G:\tools\ollama\app\ollama.exe' pull qwen3-vl:2b-instruct
& 'G:\tools\ollama\app\ollama.exe' serve

# 2) 不起服务直接验两个引擎
docker compose run --rm --no-deps `
  -v "<repo>/backend:/srv" -v "<repo>/models:/models:ro" `
  -v "<repo>/storage:/data/storage" `
  api python /srv/scripts/detect_smoke.py /data/storage/<截图>.jpg --engine dfine

# 3) 起服务后走接口
docker compose up -d api frontend
curl.exe -X POST -H "Content-Type: application/json" `
  -d '{"engine":"qwen3vl"}' http://127.0.0.1:8010/api/v1/media/<media_id>/detect
```

`.env` 需要（见 `.env.example` 与 `models/README.md`）：
`M4A_ENABLED=true`、`M4B_ENABLED=true`、`M4B_MODEL_PATH=/models/dfine.onnx`、
`M4B_MODEL_SHA256=<sha256>`、`VISION_ENABLED=true`、`VISION_MODEL=qwen3-vl:2b-instruct`。
