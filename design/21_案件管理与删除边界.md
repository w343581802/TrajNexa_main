# 案件管理：新增、切换与删除边界（2026-10-28）

> 解决的问题：主系统前端早就把「案件」写在顶栏，但它只是个静态文字，没有地方新建案件，也没地方删除；
> 上传的要素文件（原始画面 / 片段）因此没有归属。本次补齐案件管理弹窗（新增 / 切换 / 删除），
> 并明确一条硬约束：**删除案件只清理该案件上传的要素文件，录像资源一个字节都不动**。
> 录像资源功能尚未接入，删除路径里用显式占位函数说明这一点，不假装“已经处理了录像”。

## 1. 数据模型

| 表/字段 | 说明 |
| --- | --- |
| `cases`（新表，迁移 `0004_cases`） | `id` UUID、`code` 唯一（`CASE-YYYYMMDD-NN`）、`name`（2–120 字）、`description`（≤500 字）、`created_at`、`updated_at` |
| `media_assets.case_id`（新列，可空、有索引） | 要素文件归属的案件；历史素材保持 `NULL`，表示“未归属案件” |

案件与录像资源之间**没有外键**：录像文件、录像索引属于独立的录像服务（`storage/recordings` 只是本地演示目录），
主系统不保存、也不删除它们。

## 2. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/cases` | 案件列表（创建时间倒序），外层聚合出 `media_count` / `media_bytes` |
| `POST` | `/api/v1/cases` | `{name, description}`；名称 2–120 字、说明 ≤500 字；编号服务端生成 |
| `DELETE` | `/api/v1/cases/{case_id}` | 删除案件并清理该案件的要素文件；返回清理统计 |
| `POST` | `/api/v1/media` | 新增可选表单字段 `case_id`；未知案件 → 422 `unknown_case`（先校验再落盘，不留孤儿文件） |
| `GET` | `/api/v1/media?case_id=` | 只看某个案件的要素文件 |

删除返回值示例：

```json
{
  "id": "...",
  "code": "CASE-20261027-01",
  "name": "城中村西片 · 夜间轨迹研判",
  "media_files_removed": 1,
  "bytes_removed": 157433,
  "media_files_missing": 0,
  "recordings_preserved": true,
  "message": "已删除案件并清理该案件上传的要素文件；录像资源未做任何改动"
}
```

## 3. 删除边界

| 类别 | 处理 | 依据 |
| --- | --- | --- |
| 该案件上传的要素文件（画面 / 片段原件） | **清理**：先删数据库行、提交后删磁盘文件 | `case_service.purge_case_media()`；文件路径做 `is_relative_to(storage_root)` 校验，绝不越界 |
| 由这些素材派生的作业 / 报告 / 人工绑定 / 视角比较记录 | **清理**（按外键顺序：视角比较 → 绑定 → 报告 → 参考图 → 作业 → 素材） | 同上 |
| 录像文件、录像索引 | **保留，一个字节不动** | `case_service.release_recording_resources()` 是显式空实现，文档注释写明“录像资源不属于案件” |
| 未归属任何案件的旧素材（`case_id IS NULL`） | **不动** | 删除只按 `case_id` 命中 |
| TrajNexa_Map 的空间数据 / 历史素材 | **不涉及** | 主系统只读 Map |

## 4. 前端交互

- 顶栏「案件」按钮：显示当前案件名 + 编号；未选择时显示「未选择案件」并带一个「新建」提示，点击打开案件管理弹窗。
- 弹窗左侧：搜索、刷新、总数与总占用；每行显示名称、编号、说明、文件数与占用、创建时间；「当前案件」标记或「设为当前」；
  「删除」是行内二次确认，确认文案明确写出“录像资源中的视频不会被删除”。
- 弹窗右侧：新建表单（名称必填、说明限 500 字、实时显示将要生成的编号预览），下方「删除边界」说明框列出清理 / 保留 / 不涉及。
- 当前案件存 `localStorage`（`trajnexa.currentCaseId`）。切换案件会一起切换工作区：要素 / 观测 / 特征按案件在内存里隔离；
  **所有案件都从空任务态开始，没有示例数据**（刷新后案件保持，工作区回到空态）。
- 「添加目标要素」弹窗顶部显示当前案件；没有案件时阻止上传并提示先新建或选择案件。

## 5. 验证

- `backend/tests/test_cases.py`（4 例，全通过）：建案件 / 列表统计 / 上传归属；删除只清理该案件文件与派生行，
  同目录下伪造的 `recordings/CAM-01/xxxx.mp4` 仍然存在；无素材删除；非法名称与未知 `case_id` 上传不留孤儿文件。
- 全量后端用例 131 例通过（`MAP_DB_READONLY_URL` 置空以避开 Map 只读库不可达的既有失败）。
- 前端 `vue-tsc --noEmit` 通过；真实浏览器（headless Chrome + CDP）走通：新建两个案件 → 切换 → 添加要素 → 工作区隔离 →
  删除当前案件自动切换 → 删除最后一个案件回到「未选择案件」，并对每个状态截图核对。
- 真实栈上验证删除：上传 157,433 字节画面到案件 → 案件统计 1 个文件 → 删除 → 磁盘文件消失、`GET /media/{id}` 404、
  历史 23 个未归属素材仍在。

## 6. 尚未接入

- 录像资源已接线（见 `design/22`）：删除案件只删「录像目录登记 + 扫描作业 + 扫描结果行」，录像文件与目录结构不动。
- 案件与要素工作区的关系仍是前端内存态；要素 / 观测写入数据库后，应按 `case_id` 持久化并在切换时从服务端加载。
