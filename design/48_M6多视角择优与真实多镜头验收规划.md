## 7. B6-E0 缺第三镜头真值时的状态验收

### 7.1 三种状态（E0-1）

`TrackingSession.settle(analyzed_windows, remaining_actions)` 统一收敛：

| 情形 | 状态 | 理由码 |
| --- | --- | --- |
| 有候选待审、窗口已跑完 | `awaiting_review` | `candidates_waiting_for_human_review` |
| 预算不足 / 还有未跑窗口 | `budget_exhausted` | `analysis_budget_exhausted[_with_pending_review]` |

## 9. B6-F2 Truth Registry 同源核验（P1-B 收尾）

### 9.1 校验入口

`m6_view_quality.verify_confirmation(observation_id, registry=..., review_events=...,
evidence_refs=..., evidence_root=..., case_id=..., target_id=...)` 做只读同源校验，
`confirmed_target_quality()` 必须先通过它才允许标 `usable_as_target_evidence`。

校验顺序：

1. 样本必须存在且非空（否则 `no_valid_quality_samples`）；
2. 观测必须在登记器中（`observation_not_in_registry`）；
3. `case_id` / `target_id` 必须与登记记录一致（`cross_case_review` / `cross_target_review`）；
4. 不得是 `synthetic`（`synthetic_observation`）；
5. 不得 `revoked` / 有 `revoked_reason`（`confirmation_revoked`，撤销立即失效）；
6. 必须是 `human_confirmed` 且有 `reviewer`（`observation_not_human_confirmed`）；
7. 审核事件最新一条不得是 revoke/reject（`confirmation_revoked` / `observation_rejected`）；
8. 给了 `evidence_root` 时，`frame:` / `file:` 证据必须真实存在（`evidence_unresolvable`）。

### 9.2 真实核验（紫衣 B，2-1 #37）

| 场景 | 结果 |
| --- | --- |
| 真实帧 2-1/0077.jpg，目标高 127.6 px | `usable_as_target_evidence=true`，`band=high`，`evidence_checked=1` |
| 青衣候选 1-1 #225 | 拒绝 `observation_not_human_confirmed` |
| 撤销 B | 拒绝 `confirmation_revoked` |
| 用青衣 target 校验 B | 拒绝 `cross_target_review` |
| 不存在的观测 | 拒绝 `observation_not_in_registry` |
| 证据目录为空 | 拒绝 `evidence_unresolvable` |

### 9.3 一个易错点

真值包的 `case_id` 是**场景编号**（如 `purple-rider-2-2-to-2-1`），
观测记录的 `case_id` 是**案件编号**（如 `purple-rider`）。
校验用的是观测级 `case_id`，调用方不要拿包级字段去比对。

工程基线到此冻结：不再新增模型、不调 ReID 阈值、不把青衣候选升为确认。

注意：`analyze_window` 每次重新跑 ByteTrack，窗口内 track_id 与全局 `#225` 不是同一套编号，
对照只能按时间与外观分数做，不能按 id 直接相等。

### 11.4 允许的结论

“存在候选、等待人工审核”。**不能**说青衣已从 2-2 追到 1-1。

## 15. B7-A 统一模型能力层

### 15.1 能力与契约

| 能力 | 输入 | 输出 | 现有实现 |
| --- | --- | --- | --- |
| `object_detection` | image | candidates[] | D-FINE（config/detectors.json） |
| `person_reid` | image, box | vector[] | OSNet x0.25 |
| `attribute_extraction` | image, prompt | attributes{} | 接口占位，provider 未接 |
| `visual_grounding` | image, query | box, score | 接口占位，provider 未接 |

实现：`backend/app/model_capabilities.py`；配置：`backend/config/model_capabilities.json`。

### 15.2 选择与回退

解析优先级：显式 `model=` > 任务覆盖 `tasks[task]` > `default`。
主模型不可用时按 `fallbacks` 顺序降级一次，结果里带 `fallback_used`。
没有 provider 的能力抛 `capability_model_unavailable` / `capability_not_wired`，
不返回假结果。

部署可用环境变量 `TRAJNEXA_MODEL_CAPABILITIES` 指向另一份配置，业务代码不变。

### 15.3 接入点（追踪流程里只改了取值方式）

| 位置 | 改动 |
| --- | --- |
| `m6_window_analysis.analyze_window` | 检测器不再写死 `dfine-n`，改为 `model_capabilities.detector_id()` |
| `m6_person_reid._model_path` | 权重路径优先取能力配置；环境变量仍做越界校验 |
| `p6s5_one_hop_runner` | 结果写入 `model_provenance`（模型 id + 权重 sha256 前 16 位） |

### 15.4 验收证据

1. **换模型不改代码**：把配置里 `object_detection` 改成 `yolo11n`、
   `attribute_extraction` 改成 `qwen3vl`，用环境变量指向该配置重跑，
   结果 provenance 为 `yolo11n / 67d04fb4d644f5da`、`qwen3-vl:2b-instruct`，流程正常跑完。
2. **原结果可复现**：同一配置重放青衣 2-1 正推，`steps`、`candidate_pool`、`session`
   与 93651fd 逐项相等（10 条候选、窗口区间全同）。

测试：642 passed, 2 skipped（新增 `tests/test_model_capabilities.py` 10 项）。

### 15.5 明确没做

- 属性识别与目标定位只有接口，没有 provider 实现，`invoke` 会报 `capability_not_wired`；
- 没有模型管理界面、没有模型下载/升级、没有权限控制；
- 没有把 M5 的模型表整体迁入能力层，检测器和视觉模型仍读各自现有来源。
