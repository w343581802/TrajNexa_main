# B8-SA2 CV_ONLY 首轮：结构线消失点与自动降级

> 依据：《B8-S 零人工控制点自动空间标定与地图轨迹生成实施计划 V1.2》SA2 第一阶段。
> 约束：不用人工控制点、不调用 Qwen3-VL、不产生经纬度；只判断“能否从画面独立估计/校验俯角与内参”。

## 1. 已实现

`backend/app/m6_cv_self_calibration.py`

- `line_segments`：LSD（优先）→ Hough 回退，最小线长可配；
- `estimate_vanishing_point`：RANSAC 两线求交 + SVD 精化；角度残差用“线段方向 vs 中点指向消失点”；
- `_require_conditioning`：**近邻平行线族不能定出有限消失点**——内点方向跨度 <4° 或中点横向跨度 <0.2 帧宽即拒绝（`vanishing_point_ill_conditioned`）；
- `stability_check`：线段随机分两半各估一次，VP 偏差 >0.15 帧宽即判不稳定；
- `implied_focal` / `plausible_focal`：已知俯角时反推焦距，并对焦距做合理性闸门（300–4000 px）；
- `tracks_to_lines`：ByteTrack 地面接地点序列 → 直线，可与结构线合并（本轮未接真实轨迹）；
- `validate_against_pose`：与台账对照，输出 `delta_pitch_deg`、`focal_ratio`、`vanishing_point_not_on_horizon`。

测试：`backend/tests/test_m6_cv_self_calibration.py` 8 项通过（含首轮失败案例回归）。

## 2. 参考帧实测（1920×1080，台账 FOV 64、俯角 25°）

| 项 | 结果 |
|---|---|
| 检出线段 | 5843 |
| 最优消失点 | (172.0, 5.5)，167 内点，最大残差 0.346° |
| 分半稳定性 | 偏差 10.1 px（允许 288 px）→ 稳定 |
| 由消失点反推焦距 | 1146.2 px（台账 1536.3，比值 **0.746**） |
| 由消失点反推俯角 | 19.18°（台账 25°，**差 −5.82°**） |
| 台账参数对应地平线 | y = −176.4（在画面外） |
| 消失点与地平线偏差 | **181.9 px** |
| 综合判定 | `conflict`：pitch_conflict + focal_conflict + **vanishing_point_not_on_horizon** |

## 3. 解读（关键）

- 该消失点是**真实且稳定的结构线族**（167 条、分半偏差 10 px），但它**不在台账参数对应的地平线上**；
- 地面平行方向的消失点必须落在地平线上。台账 FOV 64° + 俯角 25° 把地平线推到 y=−176（画面外），因此**画面内任何消失点都不可能是道路方向**；
- 结论：这台镜头单帧结构线**无法校验俯角/内参**。这既可能是“线族来自树冠/建筑而非路面”，也可能是“台账姿态有偏差”——两者当前都无法区分，因此**不得据此修改台账，也不得输出 L2**。

这也解释了首轮实验：当时把建筑竖直线族当成道路方向，才反推出 f=130 px 的荒谬值。本次已用 `focal_out_of_range` 回归锁死该失败模式。

## 5. 下一步

1. **运动方向**：从真实录像跑出车辆/行人的地面接地点轨迹，用 `tracks_to_lines` 求道路方向消失点；车辆后退方向应指向地平线上的同一点，可与结构线交叉验证；
2. **多帧**：取 3–5 个时间段的帧，比较候选参数与 `verdict`，检验稳定性；
3. **地平线可见的场景**：若换一台俯角较小的镜头，地平线在画面内即可直接估计俯角，用于验证算法本身；
4. 只有上述证据一致时，才允许把候选参数作为“台账校验建议”，且仍需人工确认，不得自动改台账。
