# 22 录像资源接线与「添加要素」截图化

## 1. 需求（本轮）

1. 主系统不再内置演示数据：**所有新增案件都是空任务态**（无要素、无录像、研判未启动）。
2. 底部「录像资源」接线真实后端：
   - 左侧「添加视频」按钮 → 选择服务器上的录像目录（只读）；
   - 每个目录可单独开关「自动扫描」；
   - 扫描只读每段录像**开头几秒**的画面角标，识别摄像头名称与开始时间；
   - **不识别/不推断结束时间**：结束时间由后续研判真正读取录像时按读到内容累计摄像头时长。
3. 扫描结果里唯一匹配到地图台账的镜头，在地图上取消灰色；**添加要素不再点亮镜头**。
4. 「添加要素」只接受截图：选图后自动上传 + 自动识别角标；不再从媒体库挑多个素材。
5. 添加要素弹窗、按钮与时间轴不再显示 `E01` 这类内部编号；时间轴以「时间 + 摄像头名称」为主。

## 2. 后端

### 2.1 表（迁移 `0005_recordings`）

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `recording_sources` | 案件登记的录像目录 | `case_id`、`path`（相对录像根目录）、`auto_scan`、`last_status`、`last_scan_at` |
| `recording_scan_jobs` | 扫描作业（排队/运行/成功/失败） | `source_id`、`status`、`total_files`、`processed_files`、`error_message` |
| `recording_clips` | 每段录像的扫描结果 | `relpath`、`size_bytes`、`mtime_ns`、`duration_seconds`、`start_local`、`start_source`、`camera_name`、`camera_uuid`、`match_status`、`match_suggestions` |

唯一约束：`(case_id, path)`、`(source_id, relpath)`；重扫按 `size_bytes + mtime_ns` 跳过未变化文件。

### 2.2 扫描口径（`app/recordings.py`）

- 目录必须落在 `RECORDINGS_ROOT` 内，越界返回 422 `recording_path_invalid`；
- 只做目录遍历、`stat`、`ffprobe`（容器时长）、`ffmpeg` 抽帧 + 角标 OCR，**绝不写/改名/删除录像文件**；
- 抽帧偏移 `0.5s / 2.0s / 4.0s`，读到「时间 + 名称」立即停止；OCR 关闭时回退文件名里的 14 位时间戳；
- 名称匹配沿用 M1c 口径：台账规范化名称/别名**唯一精确命中**才绑定 `camera_uuid`，同名多台或相近只给建议；
- `duration_seconds` 只是技术字段，供研判累计覆盖时长，**不生成结束时间字段**。

### 2.3 接口（`app/recording_api.py`，`/api/v1/recordings`）

`GET /root`、`GET /browse?path=`、`GET /sources?case_id=`、`POST /sources`、
`PATCH /sources/{id}`（`auto_scan` / `label`）、`DELETE /sources/{id}`（只删扫描记录）、
`POST /sources/{id}/scan`（202，已有作业时 `already_running`）、`GET /sources/{id}/job`、
`GET /sources/{id}/clips`、`GET /clips?case_id=`、`GET /summary?case_id=`。

### 2.4 Worker

`run_once()` 先处理媒体预检作业，再处理录像扫描作业；主循环每轮调用
`recordings.enqueue_auto_scans(db)`：开启自动扫描且距上次扫描超过
`RECORDINGS_SCAN_INTERVAL_SECONDS`（默认 30s）的目录排一次增量扫描。
`recover_interrupted_jobs` 会把中断的录像作业重新排队。

### 2.5 删除边界

删除案件只清理「录像目录登记 + 扫描作业 + 扫描结果行」与该案件上传的要素文件，
**录像文件与目录结构保持不变**，响应带 `recordings_preserved: true`。

## 6. 「添加要素」一步到识别

入口收敛为一个动作：任何位置的「添加要素」点击后**立刻弹系统选图框**，选好文件才打开弹窗，
弹窗一出现就已经在「上传 + 识别」，不再需要用户先在弹窗里再点一次「选择截图并识别」。

- `store/workbench.ts` 新增 `pendingElementFile`（`shallowRef<File | null>`）与内部 `pickImageFile()`：
  动态创建隐藏 `<input type="file" accept="image/*">`，在点击手势内同步 `click()`，
  选中后 `resolve(file)`；取消（`cancel` 事件 / 窗口回焦兜底）`resolve(null)`，并移除 input、释放防重入标记。
- `actions.openAddElement(elementId?)`：
  - 传 `elementId`（编辑已有要素）→ 只开弹窗，不选图；
  - 未选案件 → 提示「请先新建或选择案件」，打开弹窗显示未选案件态，不弹选图框（上传必失败）；
  - 否则 `await pickImageFile()`，拿到文件写入 `pendingElementFile` 后再 `ui.addElementOpen = true`。
- `modals/AddElementModal.vue`：`uploadFile(event)` 拆成 `upload(file)`（上传 → `recognize()`）；
  打开弹窗的 watcher 在 `resetForm()` 之后取走 `pendingElementFile` 并 `void upload(file)`，
  所以弹窗出现即开始识别，进度条与「识别依据」照常工作；弹窗内「选择截图并识别」仍保留用于重选。
- 编辑已有要素不触发选图，保持原表单回填逻辑。
