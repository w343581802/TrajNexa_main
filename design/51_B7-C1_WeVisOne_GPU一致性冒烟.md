# B7-C1 GPU 一致性冒烟：WeVisOne-2B CPU BF16 vs GPU BF16

日期：2026-11-04
状态：6 张 person 裁剪的一致性验证；不重跑 20 张，不改 B7-C1 结论。

## 1. 要排除的变量

B7-C1 的 WeVisOne 结果是本机 CPU 跑的，而官方引擎 CPU 默认 FP32；我为了放下 4B 把 CPU 改成了 BF16。因此需要确认：

- 0/20 JSON、只输出 `<ref>/<box>`、不回答属性，是模型任务偏好，还是 CPU/BF16 造成的退化。

本次只换设备/精度路径，其余全部一致：

| 项 | CPU 路径 | GPU 路径 |
| --- | --- | --- |
| 权重 | tencent/WeVisOne-VL-2B | 同 |
| 精度 | bf16（引擎补丁） | bf16（官方默认） |
| 图像 | 同一裁剪 PNG | 同 |
| 提示词 | A（JSON）/ B（自然语言） | 同 |
| max_new_tokens | 192 | 192 |
| 代码 | 同一 checkout，仅 device 参数不同 | 同 |

环境：RTX 3060 Laptop 6 GB，torch 2.11.0+cu126，CUDA 12.6。加载后显存 4.90 GB，峰值 4.94 GB（6 GB 卡可以放下，但余量很小）。

样本：O02 / O01 / O03 / O05 / O07 / O09 的 person 裁剪，对应清晰、背面、远距离、载儿童、无车辆、无同伴六类。

## 2. 结果

ref 文本（模型输出的对象短语）12/12 完全一致；差异只在框坐标的数值抖动和个别 `<OBJ>` token。

| 样本 | ref 文本 | 坐标长度 | 最大坐标差（0–1000） | 文本逐字相同 | CPU 耗时 | GPU 耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| O02 2-1/0285 | 一致 | 一致 | 16 | 是 | 16.2 s | 8.7 s |
| O01 2-2/0334 | 一致 | 一致 | 12 | 否（差 12） | 18.1 s | 6.8 s |
| O03 2-2/0404 | 一致 | 一致 | 8 | 是 | 17.1 s | 8.0 s |
| O05 1-1/0350 | 一致 | 一致 | 16 | 是 | 18.1 s | 7.3 s |
| O07 2-1/0400 | 一致 | 一致 | 14 | 是 | 18.0 s | 6.8 s |
| O09 1-1/0450 | 一致 | 一致 | 26 | 是 | 16.8 s | 7.5 s |

（坐标差取 JSON 提示那一轮；文本提示仅有 O01 出现 12 个单位的差异。）

两种设备、两种提示下，输出形态完全相同：

- 不产出 JSON；
- 把“garment_color”“穿什么颜色的衣服”等提示短语当作指代目标逐一框出；
- 不给出衣着/车辆/同行的属性答案；
- 没有任何 `unknown` 语义。

## 3. 结论

1. **CPU BF16 不是 B7-C1 低分的原因**。GPU BF16 下行为不变，只有数值抖动（最大 26/1000，约 33 px）。
2. **0/20 JSON、只出 ref/box 是模型的任务偏好**，不是精度或硬件问题；继续用提示词诱导 JSON 没有证据支持。
3. **GPU 的收益只有速度**：6.8–8.7 s vs 16.8–18.1 s（约 2.2×），显存 4.94 GB。
4. 这仍是 6 张冒烟，不足以证明所有难例上完全一致；但它足以排除“CPU 精度导致属性识别失败”这个解释。

## 4. 影响

- B7-C1 的结论不变：WeVisOne 的强项是定位/计数/检测类输出，属性只能作为 caption 弱证据；
- 若后续要给 WeVisOne 定位任务上 GPU，6 GB 显存可用但余量小，batch 必须为 1；
- 属性模型的选择仍应基于能回答“unknown”的模型，而不是能输出 JSON 的模型。
