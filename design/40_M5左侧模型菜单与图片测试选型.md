# 40｜M5 左侧模型菜单与图片测试选型（实现说明）

> 日期：2026-11-01
>
> 范围：**参考 Rebucca 的左侧“小模型管理 / 大模型管理”入口**，在 TrajNexa 保持地图研判工作台的同时增加两个可操作的模型目录与选择页。此次是 Demo 图片阶段，不代表模型上传/删除、统一 Provider DB、Prompt 发布或多视频调度已完成。

## 1. Rebucca 源码参考

- `yuturuishi/rebucca/templates/app/base.html`：左侧导航 `/smallmodel/index` 和 `/llm/index`；
- `templates/app/smallmodel/index.html`：小模型注册、引擎、权重、启停、探测与测试；
- `templates/app/llm/index.html`：大模型连接、编辑与图片测试。

**TrajNexa 不照搬 Rebucca 的 Django 后台/数据库或布控报警 UI**，而是保留案件/地图工作台并采用 Vue 单页中新的左侧导航。

## 2. 实现入口

```text
TrajNexa 顶栏不变
    │
    └─ 左侧菜单（可收起）
         ├─ 研判工作台（现有地图/时间线/下部任务控制）
         └─ AI 模型中心
              ├─ 小模型管理
              │    GET /api/v1/ai/image-models（M5 Rebucca sidecar）
              │    勾选 1..5 个检测模型 → 本地保存选中 ID
              │    “进入图片测试”→ 既有「添加目标要素」上传路径
              └─ 大模型管理
                   GET /api/v1/ai/vision-models
                   单选默认视觉模型（从后端已配置列表）
                   “进入图片测试”→ 同一上传路径
    │
    └─ 添加目标要素
         ├─ Rebucca 多检测模型 → 各模型独立候选与框
         ├─ 视觉模型整图识别（作为单独对照选项）
         └─ 点击/手绘 ROI → 按左侧已选视觉模型生成外观线索
                （人员/车辆 Prompt 或本次临时编辑）
```

- `frontend/src/components/AppSidebar.vue`：新增常驻左侧可折叠菜单。
- `frontend/src/components/ModelHub.vue`：小模型和大模型目录、刷新、选择、进入图片测试；**显示“已配置”不等于“模型权重已加载”**。
- `frontend/src/store/modelChoices.ts`：仅将模型 ID 写入本机浏览器 `localStorage`，不存密钥、路径、图像、人工身份结论。
- `frontend/src/App.vue`：切换“工作台 / 小模型 / 大模型”页面；既有案件、地图工作台未重新实现。
- `frontend/src/components/modals/AddElementModal.vue`：采用左侧选中的 Rebucca 小模型（多选）及默认 VLM（ROI 描述），仍可单独切回旧 D-FINE / Qwen 作对照。
- `backend/app/m5_vision_registry.py`：服务端允许列表，默认 Qwen3-VL 2B/4B 可选；增加 `M5_VISION_MODELS_JSON` 后也可注册其他**本地 Ollama**视觉模型。
- `backend/app/m4_api.py`：新增 `GET /ai/vision-models`、可配置 `engine=vlm` 整图视觉分析及 `vision_model_id` ROI 描述。模型 ID 必须先由服务端注册，不接受浏览器指定任意 API URL 或凭据。

## 3. 小模型选择与测试

小模型目录**来自 Rebucca 图片推理服务注册结果**，不是网页虚构一个 YOLO/D-FINE 列表。Rebucca 仍由 `backend/scripts/rebucca_image_server.py` 在它自己的 Python 环境运行；配置方式见 39。

首次有模型可用时默认选第一项；可勾选多个模型（最多五个）。选择变化在“添加目标要素”内直接使用、也可在该弹窗调整。每个候选保留 `model_id/model_name` 和原始类别，结果不自动去重为已确认目标。

没有启动 Rebucca 服务时，目录显示明确错误/禁用，不影响旧引擎或手动框选。

## 4. 大模型选择与测试

目前已有 Ollama 运行接口：`VISION_BASE_URL`、`VISION_MODEL`、`VISION_MODEL_LARGE`。

默认列表对应：

| 界面 ID | 服务器设置 | 用途 |
|---|---|---|
| `qwen3vl` | `VISION_MODEL` | 视觉模型候选 |
| `qwen3vl4b` | `VISION_MODEL_LARGE` | 较大规格候选 |

增加第三个视觉模型时，在项目的**私有服务器配置**中添加：

```dotenv
M5_VISION_MODELS_JSON=[{"id":"another_vlm","name":"Another VLM","model":"实际已部署的Ollama模型标签"}]
```

该字符串是 JSON 数组，必须写入服务器环境变量而不是前端；模型必须已在本机 Ollama 实际安装。大模型管理页面的“已配置”**不是在线健康检查**，不保证模型可调用。不同供应商或远程 OpenAI-compatible 大模型的注册与密钥管理尚未实现，属于后续 M5 Provider Adapter 阶段，不应在本页假装已支持。

选择的 VLM 用于已选 ROI 的描述；Rebucca 小模型继续负责发现目标。临时 Prompt 编辑仍在“添加目标要素”里，提示词版本化发布/回滚见规划 PR #2。

## 5. 如何验收

1. 左侧菜单进入“小模型管理”“大模型管理”，原地图/时间线/任务控制仍可返回；收起/展开菜单后仍能点图标切换。
2. Rebucca 开启时从服务端列出真实注册模型；勾选两个，点击“进入图片测试”，本次检测真正带两个模型 ID；多个来源候选都有模型名。
3. 大模型切换到 4B 或一个已配置的第三方 Ollama 视觉模型，选中 ROI 后后端 `semantic_attributes.semantic_model` 与选中模型的实际标签一致；不存在的模型 ID 应 422。
4. 断开 Rebucca 服务，页面显示不可用，图片框选及旧模型路径仍正常。
5. 刷新浏览器，模型选择保留；删除/修改后端模型配置后重新刷新会按服务端列表校验本地存储的 ID，不会执行一个未注册模型。
6. 同一图像不同模型的候选框、类别与耗时做人工核对；API/构建单元测试通过并不等于车辆真实召回率已提高。
