## 4. 推荐实验架构
```text
TrajNexa_main（已有案件、证据、审核）
    │ 只读视频引用 / 结构化观测适配（实验协议）
    ▼
Rebucca Fork（原生 UI、视频输入、小模型、按需 VLM、实验输出 API）
    │
    └── 原始推理结果 + 时间来源 + 模型版本 + 失败原因
TrajNexa_Map ──只读发布空间数据──▶ TrajNexa_main
```
不在第一阶段合并数据库、不替换现有取帧器、不将报警结果当成原始检测观测。

## 5. 实验阶段与通过条件
- **E0 冻结基线**：锁定三个仓库 commit、上游 LICENSE/NOTICE、配置和硬件；备份数据库；准备有授权/脱敏的测试素材。
- **E1 上游独立运行**：验证静态图片、历史视频、RTSP（有条件时）、推理与日志。每个结论附实际命令和输出。
- **E2 解耦推理输出**：不依赖报警规则，输出逐帧 bbox、类别、分数、帧偏移/PTS 状态、模型标识、原件哈希及失败原因。若上游没有此能力，在 Fork 中新增最小实验接口。
- **E3 视觉大模型按需复核**：仅在困难画面上调用；记录模型输出与拒判；不产生自动身份结论。
- **E4 TrajNexa 适配**：保留 M4a/M4b/M4c 路径，对比独立 Rebucca 与现有实现的结果、性能、成本、复杂度；明确保留/替换/共存。
- **E5 决策**：依据复现报告选择继续 Fork、只复用组件或停止；不按演示视频主观判断。

## 6. 文档治理
每个实验都保存：`README.md`（目的/操作）、`environment.md`（commit/硬件/配置脱敏）、`results.md`（命令/输出/失败样本/耗时）、`decision.md`（结论/证据/回退）。
- 状态只允许：`待审计`、`源码确认`、`本地实测`、`验收通过`、`不采用`。
- 新增能力要登记负责系统、接口、数据归属、与现有能力的重叠、回退开关。
- 任何外部 README 功能声明不得直接写成已实测；模型权重、第三方二进制单独审核许可。
- 实验过程禁止将真实密码、录像、人脸图像、数据库备份提交 Git。
