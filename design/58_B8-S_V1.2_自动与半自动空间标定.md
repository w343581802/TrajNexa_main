# B8-S V1.2｜大规模摄像头自动与半自动空间标定实施计划

> 依据：B8-S V1.1 第 5 节 S2、B8 时间轴规划 V1.1 第 5 节。
> 本文只调整 S2 的定位与实施顺序，S0/S1/S3/S4 的结构与纪律不变。

## 1. 决策

S2 从“Map 人工标定工具”升级为“**自动、半自动、人工三级标定系统**”：

- 默认路径是**自动评估**：判断这台摄像头在现有台账与画面条件下能到哪一级空间能力；
- 只有失败、低质量或重点摄像头才进入人工精细标定；
- 人工标定退居为**复核与兜底**，不是全量接入前提。

三条不可让渡的边界：

1. **Qwen3-VL 只做场景理解与候选生成**，输出观察和不确定性，不产生经纬度，不代替 OpenCV 的单应计算；
2. **只有经过审核发布的标定才能产生 L2**；自动估计只能产出 `estimated_review_required` 候选；
3. 地图点**永远不是身份证据**，`identity_status` 保持 `candidate_unverified`。

## 2. S2 新结构

| 子阶段 | 目标 | 主要输入 | 输出 | 失败时 |
|---|---|---|---|---|
| S2-A 自动场景分析 | 识别路面、地面、消失方向、固定参照物 | 参考帧、台账姿态 | 场景结构 + 置信度 + 不确定项 | 标记 `scene_unusable`，只做 L1 |
| S2-B 自动几何估计 | 用 OpenCV + 台账参数解地面映射候选 | S2-A 结构、焦距/俯仰/安装高度 | 相机相对单应 + 不确定度 | 标记 `geometry_unstable`，不发布 |
| S2-C 自动地理参考 | 与卫星/街景/测绘数据配准 | 高质量地理参考影像 | WGS84 单应 + 米制残差 | 无影像则跳过，保持局部坐标 |
| S2-D 人工复核 | 只处理失败/低质/重点镜头 | S2-A/B/C 候选 | 审核通过的正式标定 | 拒绝并记录原因 |
| S2-E 批量管理 | 批量运行、分级、失效检测、重标 | 全部摄像头 | 空间能力分级清单 | 降级到 L1/L0 |

其中 **S2-A + S2-B 是当前优先研发路径**：不依赖额外测绘数据，就能检验“现有台账 + Qwen3-VL + OpenCV”能达到什么程度。

## 3. 第一批实验结果（2026-11-05，试点镜头 3-DX-中仁路98号-球）

参考帧：1920×1080，OSD `2026-10-29 15:00:31`。

> 时间核对：此前口头记录成 2021-10-28 是误读；以 OSD 与录像文件时间映射为准，空间观测的 `observed_at` 必须来自核验过的时间源。

### 3.1 传统几何（Hough + RANSAC 消失点）

脚本：`backend/scripts/s2_auto_scene_probe.py`

- 检出 201 条候选线，RANSAC 内点 11 条；
- 消失点 `(1029.7, 479.4)`，地平线间隙 60.6 px；
- 按台账俯仰 25° 反推焦距 `f = 130 px`，垂直视场角 152.9° —— **明显不合理**；
- 由此生成的地面点全部挤在镜头附近（坡垫 1.8 m、树池横向 15.4 m、前后向≈0），**不可用**。

结论：单帧直线 + 消失点在该场景失败。原因是路面边缘被树、车辆和阴影切断，长直线主要来自建筑竖直线，与道路方向不是同一族；台账俯仰角与画面地平线也不自洽。

### 3.2 Qwen3-VL 4B 场景结构

- 耗时 14.9 s（本地 Ollama，`qwen3-vl:4b-instruct`）；
- 输出可解析 JSON，但几何质量不可用：`horizon_y=1080`（画面底边）、道路多边形=整幅图、地面参照物落在图像右边界。

结论：4B 模型能给出场景语义，但**不能稳定给出像素级几何**。需要把任务拆小（例如只判断“消失方向在画面左/中/右”、只勾路面粗区域），并用 OpenCV 在该约束内拟合，而不是让 VLM 直接输出坐标。

### 3.3 对“三组对照”的修正

原计划的三组仍是正确方向，但第一轮证明不能只比较“谁更准”，还要比较“**谁在什么条件下可用**”：

| 组 | 现状 | 需要的改进 |
|---|---|---|
| A：Qwen + OpenCV | 语义可用、几何不可用 | 用 Qwen 输出路面掩膜/方向区间，OpenCV 在区间内拟合；提示词改为结构化小任务 |
| B：传统视觉 | 单帧消失点失败 | 多帧累积、路面语义分割（非 VLM）、车道/路缘拟合、台账姿态自检 |
| C：两者结合 | 尚未跑通 | 以 A 的掩膜限制 B 的候选线，再互检地平线与焦距 |

## 4. 评估协议（必须同时报告）

1. **有效率**：自动流程能产出可审核候选的镜头比例；
2. **几何自洽**：地平线与台账俯仰是否一致（焦距是否落在镜头合理范围，如 300–1500 px）；
3. **外部一致性**：与 OSM/卫星可见路缘、已知路宽、建筑轮廓的距离误差（需要独立参考，不能用手工点的同一批数据自证）；
4. **留出误差**：有真实地理控制点时，按 V1.1 的 P90 门限；
5. **耗时与失败类型**：每台镜头 GPU/CPU 秒数、失败原因分布；
6. **覆盖率**：不允许用“只挑好镜头”换指标，必须报告被跳过/降级的比例。

**没有独立地理参考时，只能判定“候选可信/不可信”，不能声称“误差 N 米”。**

## 5. 数据前置

- S2-C 是否可行，取决于目标区域可获得的影像质量：卫星（分辨率、拍摄时间）、街景、测绘成果；
- 在确认影像来源前，S2-C 只做接口与数据契约，不做自动匹配；
- 每台摄像头需冻结：参考帧 hash、原分辨率、裁剪/缩放、安装高度、俯仰、方位、是否 PTZ；
- 时间：OSD、录像文件时间、主系统事件时间三者必须有可核验映射。

## 6. 与 V1.1 的差异

保留：

- 人工控制点标定、留出点误差、审核发布、版本与回滚；
- `CameraGroundCalibration / CameraGroundControlPoint / CalibrationReviewEvent` 实体与主系统 L2 契约；
- L0/L1/L2 分级与降级纪律。

变化：

- 人工标定从“接入前提”变为“S2-D 兜底”；
- 自动候选与人工标定共用同一份数据契约，自动候选额外带 `source=auto`、`uncertainties`、`review_status=draft`；
- 新增空间能力分级：`L0 仅点位 / L1 视域 / L2 已审核标定 / L2-candidate 自动候选`；
- 批量指标进入 S2-E，而不是逐台人工验收。

## 7. 下一步

1. 按 3.3 改进 A/B 两组，先做到“能用/不能用”的稳定判定；
2. 跑同一参考帧的三组对照，记录有效率、自洽性、耗时、失败类型；
3. 用 S2-C 的影像可得性结论决定是否投入自动地理配准；
4. 在自动候选可信前，试点镜头仍按 S2-D 人工标定（控制点数据待补）。
