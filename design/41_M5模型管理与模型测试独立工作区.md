## 1. 最终页面职责

```text
TrajNexa 左侧
├─ 研判工作台
│    案件/目标要素/地图/轨迹候选
│    └─ 添加目标要素 → 原截图 → **业务默认模型** → 候选 → 手动确认 → 证据
│        （不显示多模型列表、引擎切换、Prompt 临时实验编辑）
└─ AI 模型中心
     ├─ 小模型管理：Rebucca 已加载检测器目录、引擎/任务/设备信息与预选
     ├─ 大模型管理：本地 Ollama + Rebucca 式远程 OpenAI-compatible API 目录
     └─ **模型测试**：独立图片上传 → 多小模型和/或多 VLM → 并排结果
                      → 点击/拖拽 ROI → 自定义 Prompt → 多 VLM 属性对比
```

**特别强调**：模型管理页面对模型的多选/首选仅作为「模型测试」的初始值，存储于浏览器本地的模型 ID，不是研判业务的默认模型配置。业务默认检测模型由服务端 `M5_WORKSPACE_DETECTOR_ID` / Rebucca 已加载模型列表决定，业务外观模型由 `VISION_FEATURE_MODEL` 决定。不能把实验配置隐式带进正式案件。

## 2. Rebucca 小模型列表的复用

Rebucca `templates/app/smallmodel/index.html` 中小模型管理主要包含：模型名称、算法/任务类型、推理引擎、设备、权重、可用性、测试入口与增删改。

本批只复用 Rebucca 的**引擎推理与实际加载的模型**，而非完整移植 Django ORM、上传管理或报警业务。目录来自本机 Rebucca sidecar `/models`，对应 `EngineFactory` 已加载的权重，不是写死的模型名称。列表列出：

| 字段 | 来源 | 用途 |
|---|---|---|
| 模型名/ID | sidecar 模型配置 | 实验选择与来源标记 |
| `algorithm_type` | Rebucca 模型配置 | D-FINE / YOLO 等算法区别 |
| `task_type` | Rebucca 模型配置 | 检测 / 分割 |
| `engine` | Rebucca `EngineFactory` | ONNX Runtime / OpenVINO / PyTorch |
| `device` | Rebucca 推理配置 | CPU / GPU 等 |
| `input_size` | 权重输入配置 | 排查小目标缩放问题 |
| `model_sha256` | 已加载权重哈希 | 可复核模型来源 |

通过左侧小模型管理页的引擎、任务筛选及多选进入「模型测试」。现阶段离线图片服务仅支持 `detect` / `segment`，ReID 需要检测裁剪＋embedding 合同，**不能声称已可独立检测**。

**重要差别**：现有 sidecar 读取自己的模型 JSON 配置（见 [39](39_M5_Rebucca图片多模型部署与验收.md)），**尚未自动同步 Rebucca Django 小模型管理数据库中新增/删除的模型**。欲完全继承 Rebucca 管理页面中所有模型，下阶段必须增加只读目录同步或可审计的模型配置导出桥，而不是重复造一套权重上传数据库。本批不承诺原生后台模型增删改同步。

## 3. 大模型：本地 + Rebucca 式远程

上游 Rebucca 大模型管理依赖 `app/utils/LLMUtils.py` 的 OpenAI-compatible 视觉接口：模型名、API URL、API key、图片＋提示词。TrajNexa 用自身的薄适配 `m5_vision_transport.py` 对接该协议，保留原有 Ollama `/api/chat`。

### 3.1 本地 Ollama

已有 `VISION_ENABLED=true`、`VISION_BASE_URL`、`VISION_MODEL` 和 `VISION_MODEL_LARGE`。两个内置 Qwen3-VL 分别列在大模型管理；通过 `M5_VISION_MODELS_JSON` 可以再注册任意已安装的 Ollama 图像模型。列表显示“本地”。

### 3.2 远程 OpenAI-compatible 视觉模型

在 **TrajNexa API 私有 `.env`** 里注册，而不是在浏览器传任意 endpoint 或 key：

```dotenv
# 与默认本地模型并存；若仅远程需要，VISION_ENABLED=false 也可工作。
M5_VISION_MODELS_JSON=[{"id":"remote_vl","name":"远程视觉模型","provider":"openai_compatible","model":"service-model-name","api_url":"https://your-provider.example/v1","api_key_env":"REMOTE_VISION_KEY"}]
REMOTE_VISION_KEY=<你的 API 密钥>
```

服务端读取 API key，浏览器目录只收到模型 ID、名称、`provider`、本地/远程标记、模型名及启用状态，不接收 API URL 或密钥。API 使用 `POST /chat/completions` 多模态 `image_url: data:image/jpeg;base64,...`。远程必须使用 HTTPS；本机 OpenAI-compatible 服务允许 `http://127.0.0.1:端口/v1`（亦可 localhost/::1）。禁止浏览器临时输入任意 endpoint，调用不跟随重定向。

**限制**：远程模型必须支持图片输入与 OpenAI-compatible 结构；并非所有「兼容 API」都支持相同图片格式。发送监控图片到远程 API 会离开本机，必须在拥有相应授权和数据保护保障的情况下才使用；默认不预置远程供应商。服务商模型名称、实际延迟与鉴权须现场测试；模型接口失败不会伪装成“画面无目标”。

本批不提供无鉴权的「浏览器新增远程 API key」按钮：Demo 没有管理登录控制，直接允许保存密钥会产生访问与泄漏风险。后续需要受控管理员凭据与加密保存/审计后再加 Rebucca 式增删改界面。目前通过服务器私有配置完成远程模型注册，前端可实际选择与调用。

## 4. 独立模型测试能力

新增只读实验 API：

| 接口 | 功能 |
|---|---|
| `POST /api/v1/ai/model-test/detect` | multipart 图片 + 1–5 个 Rebucca 小模型与/或 1–3 个已注册视觉模型；返回每模型状态、候选、时间、图片哈希 |
| `POST /api/v1/ai/model-test/roi` | 同一图片、归一化框、人员/车辆类别、最多 3 个视觉模型、本次自定义 Prompt，返回各模型属性候选与 Prompt 哈希 |

不需要 `case_id`。图片仅在内存读取（限 12MB/20MP），不写 `MediaAsset`、`TargetObservation` 或地图/案件数据库；输出 `test_only=true`，带 `source_sha256`，不得成为已确认身份。小模型仍由 Rebucca EngineFactory 推理，VLM 使用原图 ROI 先裁剪后缩放。6–8GB GPU 采用串行推理与并发上限，避免要求模型同时常驻显存。

前端 `ModelTestLab.vue` 支持本地选图、模型多选、阈值、候选框叠加、手动框选、ROI 类别与 Prompt 编辑、多模型结果、耗时与失败状态。图片测试与主工作台操作分开，不跳转到「添加目标要素」。

## 5. 主工作台整改

`AddElementModal.vue`：

- 删除 Qwen 2B/4B、D-FINE、Rebucca、VLM 的切换按钮和多小模型勾选；
- 删除临时 Prompt 编辑区和“实验选择大模型”显示；
- 保留默认检测、人工点框/手工画框、ROI 属性建议、角标 OCR、人工确认、保存证据；
- `/media/{id}/detect` 使用 `engine="auto"`，**后端**按以下顺序选择：启用 Rebucca 则用 `M5_WORKSPACE_DETECTOR_ID`（留空取服务已加载第一个）；否则有 D-FINE ONNX 权重则用 D-FINE；再否则本地 Qwen 可用则使用现有默认 Qwen；都不可用则人工框选。
- 如果 Rebucca 被显式启用但不可用，不应默默换另一模型。后端明确返回失败，主工作台继续支持人工框选。
- ROI 默认使用服务端 `VISION_FEATURE_MODEL`，不读模型测试页浏览器本地勾选项。

## 6. 验收清单

1. 进入主工作台“添加目标要素”，**不出现小模型/大模型切换与 Prompt 实验输入框**；自动候选及手动框选可正常使用。
2. 左侧进入小模型管理：列表确为 sidecar 已加载模型，能按推理引擎和任务筛选，能把多选带到测试页；断开服务给出明确错误。
3. 左侧进入大模型管理：同时显示本地 Qwen / 已注册本地 Ollama / 已注册远程 HTTPS 视觉 API，并区分标记；**模型 API key、真实 URL 不出现在响应或 UI**。
4. 左侧模型测试：选择本地图片，不需要新建案件；对同图多模型比较；ROI 原图裁剪与临时 Prompt 适用于多个视觉模型。
5. 模型离线、远程 API 失败、坏框、重复 ID、不合法图片/过大图片：错误可见，不能当作零检测；模型实验数据不写案件数据库。
6. Windows 真实模型、远程连接实测仍须验证；CI 的模拟响应与编译不能代替现场检测召回率验收。

## 8. 2026-11-01 追补：小模型 / 大模型页采用 Rebucca 的版式，配色走 TrajNexa 深色主题

**决策**：这两个页面的**结构与显示方式**照 Rebucca 的管理页（结果条 → 卡片头 → 引擎可用性条 →
七列表格 → 分页），**配色**用 TrajNexa 自己的深色主题变量（`--bg-*` / `--text-*` / `--line-*`），
以便嵌在深色的研判工作台里不割裂。数据、会话都还是 TrajNexa 自己的：不 iframe、不代理 Rebucca 登录态。

| 页面 | 列（对应 Rebucca 的列） | 数据来源 |
| --- | --- | --- |
| 小模型管理 | ID / 小模型名称 / 模型类型·任务类型 / 推理引擎·推理设备 / 分辨率·阈值 / 状态 / 操作 | `GET /api/v1/ai/image-models` |
| 大模型管理 | ID / 模型名称 / 供应商·位置 / 模型 ID / 状态 / 操作 | `GET /api/v1/ai/vision-models` |

与 Rebucca 对齐的显示方式：

- 顶部一条「模型检查结果」：全部就绪 · 共 N 个已启用小模型：成功 N 个，失败 0 个（读取失败时变红并给原因）；
- 卡片头：标题前一颗青色圆点，右侧 `全部引擎` 下拉、`↻ 刷新`、主按钮 `+ 添加小模型`（跳 Rebucca）；
- 引擎可用性条：按推理引擎汇总已加载模型数，亮/暗表示可用；
- 表格：表头两行（主字段 / 次字段）、单元格双行（`D-FINE` + `detect`、`640×640` + `conf 0.35`）；
- 状态用圆角胶囊：`启用`/`停用`、`默认`（照 Rebucca 的绿色 + 橙色）；
- 行内四个操作：`编辑`（开弹窗）、`设默认`、`测试`（跳模型测试并预选该模型）、`删除`（只读，指向 Rebucca）；
- 底部分页：`1` / `尾页` / `共 N 条`，右侧标注当前实验选择；
- 编辑弹窗字段顺序照 Rebucca：模型名称、模型类型 / 任务类型、推理引擎 / 推理设备、模型文件、
  输入宽度 / 输入高度、置信度阈值 / NMS IoU 阈值、状态 / 默认。

为此补的数据链路（阈值原来没暴露）：

1. `rebucca_chain_probe._load_detectors` 把 `conf_threshold` / `iou_threshold` 带进模型描述；
2. sidecar `/models` 输出这两个字段；
3. `m5_rebucca_client.list_models` 校验后透传；
4. 前端 `M5ImageModel` 增加 `conf_threshold?` / `iou_threshold?`，表格显示 `conf 0.35`、弹窗显示阈值。

职责边界不变：**新增/编辑/上传权重/探测仍在 Rebucca 完成**，TrajNexa 的 `编辑` 是只读详情 +
「在 Rebucca 中修改」外链（`VITE_REBUCCA_WEB_URL`，可用 `?rebucca=` 覆盖）；`删除` 明确禁用并提示到 Rebucca 操作。

本机实测（2026-11-01）：小模型页读 sidecar 的 `dfine-n` / `yolo11n`（`OnnxRuntime` 引擎条、`conf 0.35`）；
大模型页读 `Qwen3-VL 2B / 4B`（本地 ollama）；`?page=small-models&edit=dfine-n` 可直接打开编辑弹窗；
`vue-tsc --noEmit` 0 error、`vite build` 通过。

## 9. 2026-11-01 追补：引擎移植后，模型目录改由本仓库维护

| 事项 | 原描述（§2 / §7 / §8） | 现在 |
| --- | --- | --- |
| 模型来源 | Rebucca sidecar `/models` | `backend/config/detectors.json`，[42](42_检测引擎移植.md) |
| 权重 | Rebucca 上传目录 | `backend/models/`，容器内挂载 `/srv/models:ro`（不入库） |

| 页面按钮 | `+ 添加小模型` / `在 Rebucca 中修改` / `删除` 外链 | 已移除；`编辑` 为只读详情，`删除` 提示改配置 |
| 改配置 | 在 Rebucca 后台改 | 改 `detectors.json` 后调 `POST /api/v1/ai/image-models/reload` |

`POST /api/v1/ai/image-models/reload` 会重新读取配置并重建引擎；单个模型加载失败只从列表消失，
不影响其它模型，也不会让接口整体 503。

页面现在支持新增/编辑/删除检测器（写回 `detectors.json` 并热加载），字段与校验见 [42](42_检测引擎移植.md) §7；
权重上传只有接口，页面按钮还没做。
