# B8 时间轴 UI 基线 R1.9 实施计划

> 依据：用户 2026-11-06 冻结的时间轴 UI 基线（上早下晚、三类主卡、区域聚合、双向追踪、详情抽屉）。
> 定位：把现有 74 张技术卡压成“目标活动过程”主视图；时间轴仍是派生读模型，不新增事实表。

## 一、冻结的设计基线

| 设计项 | 决定 |
| --- | --- |
| 时间方向 | 始终上早下晚，不提供整体倒序模式 |
| 向后追踪 | 新发现的更晚记录从底部加入 |
| 向前追踪 | 新发现的更早记录从顶部加入 |
| 主卡类型 | 已确认轨迹（绿）/ 待核查线索（橙）/ 区域排查（蓝）；当前主视图只显示绿、蓝两类，候选收进区域详情（m03120） |
| 主卡内容 | 时间、地点或摄像头、简短结果、查看详情 |
| 区域组织 | 小范围空间相邻的摄像头网络，不等于 Run |
| 技术对象 | camera_task、候选明细、预算、日志全部收进详情 |
| 身份与空间 | 已确认只表示身份；地理坐标仍需独立 L2 审核 |
| 数据底线 | 不编造目标出现时间、位置或身份关系 |

## 三、目标读模型

新增 `backend/app/timeline_view.py`，输入仍是既有 run/window/candidate，输出主视图：

```text
GET /api/v1/cases/{caseId}/targets/{targetId}/timeline-view
{
  schema, caseId, targetId, derived: true, phase, anchorLinked,
  counts: { confirmed, review, region, total },
  cards: [
    { cardId, kind: confirmed_track|candidate_clue|region_investigation,
      observedAt, observedAtSource, timeQuality, title, place, subtitle,
      identityStatus, spatialQuality, detailCardIds, region?, candidate? }
  ],
  navigation: {
    earlier: { available, anchorCardId, observedAt, basis, enabled, reason },
    later:   { ... }
  },
  note
}
```

### 3.1 区域聚合

- 相机坐标来自 Map 只读库 `read_map_spatial`，只读、TTL 60s；读取失败时退回“完全同名镜头”分组。
- 有坐标：按 60m 连通聚类（haversine）；无坐标：一个规范镜头名一个区域，绝不按名称相似度或道路方向猜。
- 区域 id：`region:{case}:{target}:{hash(排序后的 camera_uuid 或 canonical label)}`，不基于 runId，状态变化不重建。
- 一个区域合并多个 run、多个 window；window 按 `windowId` 去重，候选按 `(camera_label, track_id, window_start)` 去重。
- 同一 track 的重复候选优先保留 `human_confirmed`，其次 `rejected`，再次 `candidate_unverified`。
- 区域卡展示计划录像范围；窗口不连续时必须标“不连续”，不能显示成一个连续区间。
- 区域卡仍保留 `region.cameraTasks`（带 `runId`）、`runIds`、预算合计与逐 run 预算，供地图高亮和详情使用。

### 3.2 三类主卡

| kind | 生成条件 | 计数 |
| --- | --- | --- |
| `confirmed_track` | 身份 ∈ confirmed/human_confirmed **且**有逐帧 frames/points | 已确认轨迹 |
| `candidate_clue` | 有候选，但无逐帧轨迹；含“身份已确认、轨迹未验证” | 待核查线索 |
| `region_investigation` | 有区域窗口/设备 | 正在排查 |

- anchor 关联成功后不再单独占主卡，收进轨迹/线索详情。
- 每个区域最多一张候选线索摘要卡（“发现 N 条候选”）+ 一张区域卡；候选切换在详情内。
- 主卡不渲染 camera_task、gap、review 事件等技术对象。

### 3.3 时间语义

- `observedAt` 只来自目标事件时间：anchor 的 `anchor_seconds`、window 的 `window_start`，经 `start_local`/`clip_start_local` + `start_of_day_seconds` 换算墙钟。
- 映射不完整：`observedAt=null`，`observedAtSource='unmapped'`，卡片排在所有已映射卡之后并标注“时间未映射”；不得用 `created_at` 冒充。
- 无法确认 PT S/OSD 一致时 `timeQuality` 保持 `uncalibrated_*`，界面不得称“精确时刻”。
- 排序只代表时间先后，不表示相邻卡片存在连续轨迹。

## 六、不做的事

- 不做整体倒序模式。
- 不把区域卡当成目标到达证据。
- 不把身份确认当成地理精度确认。
- 不用样本轨迹填充真实 run 的逐帧数据。
- 不改 TrajNexa_Map 仓库；坐标只读。
- 不在 R1.9 内实现跨镜头 ReID 或新的视觉自标定。
