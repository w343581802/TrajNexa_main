## 2. 本次已修（两处高优先）

### 2.1 删案件时比对记录漏删（PG 上会 500）

`backend/app/case_service.py` 原来写的是：

```python
conditions = [...]
db.execute(delete(ViewComparisonRecord).where(*conditions))   # 多个条件是 AND
```

`where(a, b)` 是**且**，而比对记录有三个外键（报告 / 参考图 / 绑定决策），三者可能跨案件。
只要某行只命中其中一个（例如参考图属于本案、报告属于别的案件），旧写法就漏删；紧接着
删 `camera_view_references` / `inspection_reports` 会撞无级联外键 → PostgreSQL 上
`DELETE /api/v1/cases/{id}` 直接 500，整案删不掉。

修复：改成 `or_(*conditions)`，并把 `binding_decision_id` 也纳入条件（原来只考虑了两个外键，
而 `binding_decision_id` 是非空外键，漏掉它同样会撞）。

回归用例：`backend/tests/test_cases.py::test_delete_case_purges_cross_case_comparison_records`。
它造两条「只命中一个条件」的比对记录，断言删案后一行不剩。**验证过它确实能抓到 bug**：
把 `or_(*conditions)` 临时改回 `*conditions`，该用例失败；改回来通过。

### 2.2 视频命名工具默认放行任意磁盘路径

`backend/app/media_inputs.py::allowed_roots()` 原来「没配 `VIDEO_NAMING_ROOTS` 就不限制」，
而这个工具对文件做**原地改名**、还能把文件下载回来。默认放行等于把整块磁盘交给它。

修复：没显式配置时**退回「本机真实存在的可写挂载点」**（容器里就是 `/data/video-library`），
只有连这些挂载点都不存在（本地直接跑、没有挂载）才退回不限制；要彻底放开得显式写
`VIDEO_NAMING_ROOTS=/`。同时把 `video_naming_api._safe_local_path()` 里重复的
「绝对路径 + 允许根 + 是文件」逻辑改为复用 `media_inputs.resolve_input()`，下载与改名
从此走同一个校验器（宿主机路径翻译、相对路径解析、允许根、符号链接都在一处）。

配套：

- `backend/tests/conftest.py` 增加 autouse fixture，把允许根清空并把 `video_naming_root`
  指向不存在的目录——否则容器里 `/data/video-library` 存在，所有用临时目录的用例都会被拒；
- 新增两条用例：`test_allowed_roots_falls_back_to_existing_mount`（兜底生效、目录外被拒）、
  `test_explicit_roots_win_over_fallback`（显式配置优先）。
