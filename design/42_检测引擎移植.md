# 42｜检测引擎移植：从「对接 Rebucca」改成「本仓库自带」

> 2026-11-01。目标：删掉本仓库自己那份 D-FINE 推理实现，把 Rebucca 的
> `app/analysis/engines` 引擎层整体移植进来，检测不再依赖 Rebucca 进程或 HTTP sidecar。

## 1. 移植了什么

| 来源 | 落点 | 说明 |
| --- | --- | --- |
| `rebucca/app/analysis/engines/base.py` | `backend/app/engines/base.py` | `BaseEngine` / `DetectionResult` 抽象 |
| `.../factory.py` | `backend/app/engines/factory.py` | `EngineFactory` 按引擎名 + 任务/算法路由 |
| `.../dfine_engine.py` | `backend/app/engines/dfine_engine.py` | D-FINE（onnxruntime / openvino 两个后端），无 NMS |
| `.../onnx_engine.py` | `backend/app/engines/onnx_engine.py` | YOLO 系 ONNX + `yolo_postprocess.decode_outputs` |
| `.../openvino_engine.py` | `backend/app/engines/openvino_engine.py` | OpenVINO 后端（依赖可选） |
| `.../yolo_pytorch_engine.py`、`pytorch_engine.py` | 同名 | ultralytics / torch 后端（依赖可选） |
| `.../reid_onnx_engine.py` | 同名 | ReID 嵌入模型 |
| `.../yolo_postprocess.py` | 同名 | YOLO 输出解码 |
| `rebucca/app/utils/seed_defaults.py: COCO_80_CN` | `backend/config/labels/coco80_zh.txt` | 80 类中文标签（D-FINE 需要按序标签） |

移植时只改了包路径（`app.analysis.engines` → `app.engines`），并在文件头保留上游署名与开源地址；
引擎行为（含 D-FINE 不做 NMS 这一点）与 Rebucca 一致。

## 2. 新增的本仓库组件

| 文件 | 作用 |
| --- | --- |
| `backend/app/engines/` | 引擎层（自 Rebucca 移植） |
| `backend/app/detectors.py` | 检测器注册表：读配置、加载引擎、`list_models()` / `detect()` / `detect_flat()` |
| `backend/app/media_image.py` | 从旧 `m4_detection` 抽出的哈希校验解码 |
| `backend/config/detectors.json` | 检测器清单（受版本管理） |
| `backend/config/labels/coco80_zh.txt` | COCO80 中文标签 |
| `backend/models/` | 权重目录（`.gitignore` 已忽略 `models/` 与 `*.onnx`） |

配置示例：

```json
{
  "detectors": [
    {
      "id": "dfine-n",
      "name": "Rebucca D-FINE N",
      "engine": "onnxruntime",
      "algorithm_type": "dfine",
      "task_type": "detect",
      "device": "cpu",
      "model_file": "models/dfine/dfine_n_coco_opset17_fp32_static.onnx",
      "labels_file": "config/labels/coco80_zh.txt",
      "input_width": 640,
      "input_height": 640,
      "conf_threshold": 0.35,
      "iou_threshold": 0.5
    }
  ]
}
```

路径相对 `backend/` 解析；`M5_DETECTORS_CONFIG` 可指向另一份配置。

## 3. 删掉了什么

- `backend/app/m4_detection.py`：本仓库自己那份 D-FINE ONNX 推理（含切片、`parse_hf_outputs`、`_nms`）；
- `backend/app/m5_rebucca_client.py`：调 sidecar 的 HTTP 客户端；
- `backend/scripts/rebucca_image_server.py`、`rebucca_chain_probe.py`：sidecar 与离线探针；
- `backend/scripts/detect_smoke.py`、`detect_eval.py`：绑死旧 D-FINE 的脚本；
- 相关测试：`test_m4b_detection.py`、`test_m4b_preview_api.py`、`test_m4d_detect.py`、
  `test_m5_rebucca_image.py`、`test_m5_rebucca_contract.py`、`test_m5_rebucca_probe.py`；
- 配置项：`M4B_ENABLED` / `M4B_MODEL_PATH` / `M4B_MODEL_SHA256` / `M4B_TILING` 与 `M5_REBUCCA_*`。

## 4. 行为变化

- `/api/v1/ai/image-models` 现在读本机 `detectors.json`，`enabled` 表示「有可用检测器」；
- `/api/v1/media/{id}/detect` 的引擎值：`local`（新名）与 `rebucca`（旧名）等价；`auto` 仍由服务端按
  `M5_WORKSPACE_DETECTOR_ID` 选一个，不读浏览器的实验选择；
- `/detections/preview` 保留，改为走本机默认检测器；
- 错误码统一成 `detector-*`（如 `detector-inference-failed-<id>`），不再出现 `m4b-*` / `m5-rebucca-*`；
- 模型页不再外链 Rebucca：目录、阈值、权重都来自本仓库配置。

## 5. 验证

- 本机加载 `dfine-n` + `yolo11n` 直接推理（1920×1088 一帧）耗时 0.60s，两模型均返回候选；
- API 容器重启后 `/api/v1/ai/image-models` 返回两个检测器与 `conf_threshold`；
- 测试：257 passed / 2 skipped，剩余失败是既有基线（`m1a` 摄像头匹配、`m1b` OCR、`m1c`/`m1d` 报告链）；
- 前端 `vue-tsc --noEmit` 0 error、`vite build` 通过。

## 6. 部署与运维（2026-11-01 补齐）

- api / worker 通过 compose 挂载 `./backend/config:/srv/config:ro` 与 `./backend/models:/srv/models:ro`，
  重建容器不需要再 `docker cp`；
- 手改 `detectors.json` 后调 `POST /api/v1/ai/image-models/reload` 热加载，不用重启；
- 推理串行由 `app/detectors.py` 内的 `detector_busy` 锁统一保证，工作台、模型测试、视频采样共用；
- 旧的 `compose.m4b.yaml` / `Dockerfile.m4b` / `requirements-m4b.txt` 已删除，ONNX Runtime 在主镜像里。

## 7. 模型管理：页面上可增删改（2026-11-01）

| 操作 | 接口 | 行为 |
| --- | --- | --- |
| 新增 | `POST /ai/image-models` | 校验 ID/引擎/算法/权重/标签 → 追加到 `detectors.json` → 热加载；失败回滚 |
| 编辑 | `PUT /ai/image-models/{id}` | 只能改名称、置信度、NMS IoU、设备；失败回滚原文件 |
| 删除 | `DELETE /ai/image-models/{id}` | 只从配置移除，**不删权重文件** |
| 重载 | `POST /ai/image-models/reload` | 手改 JSON 后按一下 |
| 权重列表 | `GET /ai/image-models/weights` | 列出 `models/` 下可用权重，供新增时选择 |
| 上传权重 | `POST /ai/image-models/upload` | 存到 `models/uploads/`，返回相对路径与 sha256（页面暂未接按钮） |

页面行为（照 Rebucca 管理页）：卡片头 `+ 新增小模型`、`↻ 重载配置`、`刷新列表`；行内 `编辑` 打开可保存表单、
`删除` 二次确认；`设默认`/`测试` 仍只影响模型测试的勾选，不改研判工作台默认模型。

配置与权重挂载必须是可写：`./backend/config:/srv/config`、`./backend/models:/srv/models`（不能带 `:ro`），
否则页面保存会 500。

## 8. 候选框契约（2026-11-01 修）

引擎层给的是**像素框**（`box` + `label` + `score`），界面按 **归一化坐标** 画框。移植时少了这一层转换，
页面拿到没有 `bbox_normalized` 的候选，渲染函数读 `bbox_normalized[0]` 直接抛 TypeError，
组件更新失败 → 按钮永远停在「正在逐模型检测…」。

现在由 `detectors.proposals(candidates, (w, h))` 统一转换，接口与工作台共用：

| 字段 | 来源 |
| --- | --- |
| `bbox_normalized` | 像素框 ÷ 图宽高，裁剪到 [0,1]，零面积框丢弃 |
| `object_class` | 标签下标 0→person，1/2/3/5/6/7→vehicle，其余 other；中文标签名同样识别 |
| `detector_label` / `confidence` | 引擎标签与分数（裁剪到 [0,1]） |
| `model_id` / `model_name` | 产出该候选的检测器 |
| `status` | 固定 `unverified_detection_proposal` |

用到的三个接口：`/media/{id}/detect`、`/media/{id}/detections/preview`、`/ai/model-test/detect`。
页面侧再加一层防御：坐标不合法的候选不参与渲染，单个坏候选不会再让整块画布白屏。

## 9. 还没做

- 权重不入库：换机器要把 `backend/models/` 下的 ONNX 放好；
- 上传权重只有接口，页面还没有上传按钮（Rebucca 是弹窗里直接选文件）；
- OpenVINO / PyTorch 引擎已移植但本机未装依赖，未做真机验证；
- D-FINE 不做 NMS 的原行为保留，同目标可能出多个框，尚未做显示层去重。
