# M1d｜固定场景参考图与视角一致性校验（TrajNexa 主系统 Demo）

> 版本：0.1，2026-10-25。只处理**静态背景**与参考图的对应情况，不进行人员跨镜头关联。实际 Docker / 真实监控夜间场景准确率仍待验收。

## 模块目标和边界

从预检结果确认摄像头来源后，对比收到的截图/视频帧与人工登记的该设备固定场景参考图。用于发现**疑似视角变化**，辅助发现 TrajNexa_Map 记录与现场画面的不一致情况。

1. 已上传素材的 M1c 人工绑定记录必须是最新 `confirm`，撤销后不可做新的视角校验。
2. 参考图必须是已上传的**图片**，须有来源说明、相机 UUID、目录快照版本和 SHA-256；参考图登记不修改媒体原件或 TrajNexa_Map。
3. M1d 先使用 M1c 的 `storage/camera_catalog.json` **演示目录**；尚未调用真正的 TrajNexa_Map API。
4. 目录快照哈希发生变化时，旧绑定和旧参考图需要重新核实，接口返回 `catalog_revision_changed`，不会自动继承旧校验结论。
5. 对比采用 OpenCV ORB 描述子、汉明距离比值筛选与 RANSAC 单应性。遮蔽顶部和底部各 12% 的典型角标区域，缩放超大画面避免无界计算。
6. 对录像最多在三个时间点抽帧；无法读取、低纹理、夜间红外变化或背景遮挡导致匹配失败时一律 `indeterminate`，**不宣称镜头一定偏了**。
7. 有足够分布范围的静态对应点时输出 `reference_view_consistent_candidate`；同一组对应点显示较大像素位移时输出 `possible_view_change`。**这两个标签都是候选，需要人工审核**，不等于确认绝对朝向或 FOV 几何准确。
8. 输出参考文件哈希、当前文件哈希、使用的目录版本、人工绑定决策 ID、各帧匹配数量、内点比例、像素相对位移和所有比较历史。原始 OCR 预检报告保持不变。

## API（Demo）

| 方法 / 路径 | 描述 |
|---|---|
| `POST /api/v1/cameras/{camera_uuid}/view-references` | 以 `{media_id,note}` 登记已有图片为人工参考图 |
| `GET /api/v1/cameras/{camera_uuid}/view-references` | 查询参考图记录 |
| `POST /api/v1/inspections/{inspection_id}/view-checks` | 传 `{reference_id}` 对已人工绑定素材执行静态背景比较 |
| `GET /api/v1/inspections/{inspection_id}/view-checks` | 查询不可覆盖的检查历史 |

新增数据库表：`camera_view_references` 和 `view_comparison_records`，迁移脚本 `0003_m1d_view_reference.py`。

## 验证要求

执行 `cd backend && python -m pytest -q`，包含合成纹理的相同场景/平移场景、随机不同画面、低纹理、错误摄像头、撤销绑定、目录版本变更、原件 SHA-256 被篡改和录像帧读取失败。

目前只能验证算法实现和测试样本，不是实景准确率：下一轮需选取**授权的**白天/夜间/红外固定镜头、PTZ 变焦、施工变化、天气遮挡、时间角标不同区域等样本，人工标注真实视角变化并统计误报/漏报。

## 与地图的职责边界

TrajNexa_Map 负责摄像头绝对地理朝向、FOV 的编辑、版本和发布；M1d 只能对比当前像素与参考像素，**无法推算绝对地理角度差值**。需要校准地理方位时，后续另做已知坐标参照点或相机标定，不能用 OpenCV 特征匹配结果假装已经得出 `heading_difference_deg`。

当前 API 无用户权限，只建议本地回环部署；严禁将真实监控素材、设备密钥、数据库或 `.env` 提交公开 GitHub 仓库。
