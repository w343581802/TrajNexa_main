# 固定字体数字分割与逐字符识别：TrajNexa 独立实验

> 2026-10-26 · 实验状态：已实现和本地验证；**不修改生产 PP-OCRv6 / MediaInspector**。公开仓库不包含任何真实截图。

## 目的

现有 PP-OCRv6 在用户提供的两张监控截图中，将 `2026-10-23` 中的日期十位 `2` 漏识别为 `2026-10-3`。本实验针对**固定摄像头、固定角标位置和固定字体**，把日期的八位数字 `YYYYMMDD` 逐个裁切，再用另一张人工核实的参考图字形做相似度匹配（OpenCV）。不识别时分秒，不推断拍摄时区。

入口：`backend/scripts/benchmark_fixed_osd_digits.py`。仅依赖主 Worker 已有的 OpenCV 与 NumPy，不额外安装 OCR 引擎，也不替换 PP-OCRv6。

## 方法与安全边界

1. 针对这组 **1920 宽、右上时间角标**独立标定八个数字位置（不能通用于其他镜头）；宽高不同时做比例缩放。
2. 用**不同文件且不同字节内容**的人工核实参考截图建立该镜头的数字模板；不允许用待测图片本身训练后评分。
3. 对各数字位置分别执行模板比较，允许很小的像素偏移；依据相似度与第一、第二候选差距决定是否接受。
4. 弱匹配输出 `?`，整段日期为 `indeterminate`；合法的候选日期也只能表示 `complete_candidate_unverified`。**不根据文件名、人工目标日期或其它 OCR 输出填补字符**。
5. `--expected` 只用于计算实验的完全匹配布尔值，不影响推理输出。历史预检报告、原始素材以及 TrajNexa_Map 数据不受影响。

## 真实样本实验结果

用之前提供的**同一固定摄像头、同一天**的两张真实截图进行了双向交叉测试：

| 实验方向 | 当前截图的人工核实日期 | 固定字形实验输出 | 日期字段 |
|---|---|---|---|
| 14:59 截图做参考 → 15:17 截图待识别 | 2026-10-23 | 2026-10-23 | 完整匹配 |
| 15:17 截图做参考 → 14:59 截图待识别 | 2026-10-23 | 2026-10-23 | 完整匹配 |

日期十位 `2` 的独立模板匹配得分约 `0.961`，但此分数**不代表时间真实性的概率**。

此前用户在其 OCR Worker 上实测：15:17 截图 PP-OCRv6 12 组完整时间组合 `0/12` 完全正确；14:59 截图曾得到日期缺字 `2026-10-3/14:59:59`。与本实验相比，固定字形策略在**日期字段**上看起来更好，但这是 **2 张同摄像头、同日期图片的探索性结果**，并非跨设备泛化成绩，也不是相同硬件上重跑的 PP-OCRv6 时间性能基准。

## 用户本机复验

把两张不同的授权测试截图放在本机项目 `storage/validation/` 中，不要提交到公共仓库。第一张作为参考，第二张作为待检；参考日期必须经人工读图确认。

```powershell
git pull
docker compose up -d
docker compose exec -T worker python scripts/benchmark_fixed_osd_digits.py `
  /data/storage/validation/reference.jpg `
  /data/storage/validation/query.png `
  --reference-date 2026-10-23 `
  --expected 2026-10-23 `
  --output /data/storage/validation/fixed_digit_result.json `
  --preview-dir /data/storage/validation/digit_preview
```

输出包含每个数字的 `candidate`、`accepted`、`similarity`、`runner_up_margin`，完整日期候选与拒判状态。预览字符裁切为本地私有数据，不要提交。

## 实验局限和下一步

- 模板类只含该参考日期出现过的数字（例如目前 `0,1,2,3,6`），**未见过的数字无法可靠识别**；改变日期就必须引入独立参考样本或更新模板。
- 相同日期、相同位置、相似背景使两幅图高度相关，`2/2` 不能证明换天、换镜头、换红外模式准确。
- 缺字被遮挡时输出拒判，比误接受日期更重要。需要用不同日期与不同背景的留出样本评估**正确率、误接受率、拒判率、耗时**。
- 前端、数据库、生产 OCR API 此轮均不变；是否作为 PP-OCRv6 的补充路径，取决于下一批真实样本验证。
