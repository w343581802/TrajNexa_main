# M1 P0 修复：时间角标日期回溯导致静默错时

用户实测：OCR 原文 `2026-10-23:14:59:59` 可能被旧正则识别为 `2026-10-02T03:14:59`，因为冒号不在日期/时间连接符集合中，正则回溯使日期末位变成小时数字。

- 在 `backend/app/overlay_ocr.py` 中补充 `:` 作为日期/时钟分隔符。
- 同一时间解析器被正式 MediaInspector 与 PP-OCRv6 实验脚本复用；新增专项回归测试。
- 原始 OCR 字符串、文件名提示、历史报告均不改变；重新发起预检后才会生成新报告。
- 单位数日期 `2026-10-3` 仍只得到未经验证的 `2026-10-03` 候选，不能据此确认日字段未漏字。

回归命令：`cd backend && python -m pytest -q tests/test_m1g_colon_timestamp.py`。

**验证范围：** 本次纯日期解析修复无需 GPU / PaddleOCR 模型，但需在用户真实 Docker Worker 再运行一次实拍图复核。
