# 23_底部控制栏重构（任务控制 / 录像资源 / 候选结果）

> 目标：把底部控制栏从「五分区 + 折叠详情行」改成**左右两栏**的工作区，
> 「正在分析」分区取消、并入「任务控制」，录像资源与任务控制都拆成左控制 / 右内容。

## 1. 新的分区结构

```
任务控制 | 录像资源 | 候选结果 | 历史记录        ← 左侧竖排（原 5 个 → 4 个）
```

| 分区 | 左栏 | 右栏 |
| --- | --- | --- |
| 任务控制 | 轮次摘要 + 「启动后在做什么」文字 + 继续/暂停/终止 + 要素/作业/分析中/待审核 + 录像索引 | 正在分析的摄像头视频（卡片，无进度条） |
| 录像资源 | 添加视频 / 挂载目录 / 开启分析 / 自动分析 + 已登记目录列表 | 视频文件信息表 |
| 候选结果 | — | 已分析视频统计 + 按摄像头统计 + 候选条目 |
| 历史记录 | — | 轮次历史（仍为空态） |

## 2. 任务控制

左栏（控制 + 基本信息）：

- 轮次：`R2`、起始要素 · 向前倒查、时间范围 `18:00–20:12`。
- **「启动后在做什么」一块文字**（替代原来的 5 段进度条）。视频研判本身就是不确定的：同一段读完了可能无检出、可能要人工确认，给百分比只是假装确定，所以这里只写状态与正在做的事，由 `activityView` 按作业状态生成：

  | 情形 | 文案（标签 / 说明） |
  | --- | --- |
  | 未启动 | 尚未启动 / 添加目标要素、设定时间范围后才会开始读录像 |
  | 有作业在跑 | 正在分析「金水路-东向卡口」/ 18:00–20:12 · 正在这段里比对目标的外观特征；另有 2 段同时在读 |
  | 有作业排队 | N 段排队中 / 前一段读完后自动开始，不需要手动推进 |
  | 有待审核 | N 段等待人工审核 / 先看「…」这一段：确认后进候选，排除后不再计入 |
  | 有失败 | N 段读取中断 / 录像可能损坏或被占用，可重新排队 |
  | 已暂停 | 已暂停 / 已读完的片段与证据都保留，恢复后从下一段继续 |
  | 本轮结束 | 本轮已结束 / 结论与审核记录留在历史里 |

  状态点颜色跟着走：分析中=蓝、待审核/暂停=琥珀、失败=红、结束=绿、闲置=灰。
- 控制按钮：继续分析 / 暂停 / 终止。
- 一行小字：要素 / 作业 / 分析中 / 待审核（待审核非 0 时变琥珀色）。
- 底行：录像索引（文件 / 有时间 / 匹配）+「添加」快捷入口。

右栏（分析卡片，`components/dock/JobCard.vue`）：

```
┌──────────┬────────────────────────────┐
│ 缩略图   │ 摄像头名称                  │
│ 96×54    │ 18:00–20:12                │
│          │ 模型分析中                  │
└──────────┴────────────────────────────┘
```

- 卡片左侧是缩略图或缩略视频，**统一由右栏顶部「缩略图 / 缩略视频」开关控制**（不逐卡片单独设置），
  选择记在 `localStorage.trajnexa.dock.thumbMode`，下次打开沿用。
- 卡片右侧：摄像头名称、分析时间、状态文字（排队中 / 读取中 / 模型分析 / 结果整理 / 待人工审核 / 已完成 / 无检出 / 失败 / 已取消）。
  **没有进度条、没有百分比**，三段文字，字号 13 / 11.5 / 11.5px。
- **需要人工审核的卡片自动排到最前**（`needsReview` 或 `status === "review"`），并高亮：琥珀描边 + 左侧 2px 色条 + 浅琥珀底 + 「待人工审核」字样。
- 点卡片 → `components/modals/ClipReviewModal.vue`：左侧片段区（有缩略帧/片段地址就显示，没有就显示占位与说明），
  右侧录段时间、文件、所在目录、匹配状态、相近镜头建议、审核备注；底部「稍后再说 / 排除 / 确认候选」。
  不需要审核的卡片打开时标题是「分析片段」，只保留「关闭」，不会给出确认/排除按钮。

## 3. 录像资源

左栏：

- **添加视频**：打开 `RecordingDirModal`（文件选择框）——逐级点进目录，点中一个视频文件会打勾并提示
  「确认后登记它所在的目录」；确认按钮是「添加「目录名」的视频（N 个）」，没有视频时置灰并写明原因。
- **挂载目录**：同一个选择器，文件行只做展示，确认按钮换成「挂载「目录名」」。
- 选择器本身：面包屑 + 根目录 / 上一级 / 刷新三个按钮，目录行显示「N 个视频」，文件行显示大小；
  数据来自 `GET /recordings/browse?path=`，登记的是**当前目录**（后端按目录扫描，做不到只扫单个文件）。
  接口 404 / 连不上时给中文说明 + 「重试」，不再把 `Not Found` 原样甩给用户。
- **开启分析**：对还没在扫描的目录逐个发起扫描/解析（`POST /recordings/sources/{id}/scan`）。
- **自动分析**：一次性把所有目录的 `auto_scan` 打开/关闭（也保留每个目录单独的小勾选）。
- 目录列表：名称、扫描状态、文件/匹配数、单目录「自动 / 扫描 / 移除」。

右栏：

- 视频文件信息表：开始时间（OCR/文件名来源）、摄像头、文件名、时长、匹配状态；按开始时间倒序，最多渲染最近 200 行并提示总数。
- 空态分三种：未选案件 / 读取中 / 读不到或还没扫描。

## 4. 候选结果

「候选结果」不再只是候选条目列表，而是**已经分析过的视频**的统计：

| 指标 | 含义 |
| --- | --- |
| 已分析视频 | 已经跑完的作业数（不含排队/读取中） |
| 有检出 | 状态 done 的作业 |
| 无检出 | 状态 nodetect |
| 待审核 | `needsReview` 或 `status === "review"` |
| 失败 | 状态 failed |
| 候选总数 | 各作业 candidates 之和 |

下面两张小表：按摄像头统计（已分析 / 检出 / 待审）与候选条目（点一条会同步地图与时间线选中）。

## 5. 数据边界（重要）

- **分析作业目前没有后端**：`jobList` 由前端维护，当前恒为空，所以卡片区默认显示空态，
  文案按「有没有要素」区分（先加要素 → 去录像资源添加视频）。
  卡片、排序、高亮、审核弹窗都已按真实数据形状写好，作业接上后直接渲染。
- **缩略帧 / 片段播放接口没有提供**：卡片与弹窗都留了 `thumbUrl` / `clipUrl` 槽位，
  有地址就显示图/视频，没有就显示「缩略帧待生成」「缩略视频待生成」占位，不伪造画面。
- **审核结论暂存前端**：确认/排除只改前端作业状态与候选数，提示语写明「结论记在本轮审核记录里」；
  后端审核接口接入后由 `actions.reviewJob` 回写。
- **不给进度百分比**：视频研判本身不确定（同一段读完可能无检出、可能要人工确认），
  所以任务控制左栏用 `activityView` 的文字说明代替原来的 5 段进度条，卡片也去掉进度条与 `46%` 这类数字。
  作业对象里的 `progress` 字段仍在（后端已经会给），只是不再上屏。
- **开启分析 ≠ 模型分析**：现在只做扫描与索引（真实接口），toast 里写明「模型分析服务尚未接入」。
- 录像资源接口在后端 `app/recording_api.py`（`/api/v1/recordings/*`）；api 镜像早于这套路由时会 404
  （2026-10-29 重建过 `api` / `migrate` / `worker` 镜像后恢复正常），前端会把错误显示在右栏顶部与选择框里，不白屏。
