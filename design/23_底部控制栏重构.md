## 8. 侧栏切换不销毁研判工作台（2026-11）

原先 `App.vue` 用 `v-if / v-else` 切换页面，点「录像资源」等菜单会把 `.workspace` 整个卸载；再回来时地图、时间线、目标特征栏重新挂载，地图视野、图层开关、选中锚点卡片、时间线排序等组件本地状态全部重置，看起来像“研判数据消失”。

改为工作台常驻，切页只加 `.is-hidden`：

```css
.workspace.is-hidden {
  position: absolute;
  inset: 0;
  visibility: hidden;
  pointer-events: none;
  z-index: -1;
}
```

- 地图仍按工作台真实尺寸布局，不经过 `display:none`，不需要 `invalidateSize()`，避免重新量尺寸后地图跑偏；
- 页面组件不再重挂载，Pinia 之外的本地状态（地图视野、图层开关、锚点卡片、时间线排序）保持；
- 其它页面仍是独立 `v-if`，录像资源的 4 秒轮询只在进入该页时启动，离开即停止。

真实浏览器验证：注入 1 个目标要素 → 切「录像资源」→ 切回「研判工作台」，`storeElements=1`、时间线 1 条、底栏“要素 1”、地图视野与锚点卡片均保持；录像资源页不叠加隐藏地图。

## 9. 有录像却显示「等待录像」（2026-11）

根因有两层：

1. `jobList` 只有 mock 初始值，添加要素/扫描录像后没有任何代码把真实 `recordingClips` 变成作业，底栏自然落到兜底文案「已启动，等待录像」；
2. `wb.from/to` 是硬编码 `18:00–20:12`，地图上方时间范围只改 `timeWindow`，两份时间不联动。录像实际是 14:59–15:00 时，即使有作业规划也永远匹配不到。

修复：

- `plannedJobs` 按「锚点日期 + 锚点镜头 + 当前时间窗」从 `recordingClips` 生成 `queued` 作业，真实文件、开始时间、时长、缩略帧都来自扫描结果；未绑定锚点镜头时只排已匹配到 Map 镜头的片段，未匹配片段先留在录像资源核对。不伪造分析结论。
- 第一次添加要素时，范围自动落到要素时间前后 2 小时，并扩展到同一天已扫描录像的最早/最晚时间；用户手动改过时间范围后不再自动改。
- 地图时间范围、顶部时间范围、`wb.from/to` 改为同一份状态；手动调整会同步。
- 没有匹配时不再笼统说「去添加视频」，而是区分「录像不在当前时间窗」「没有锚点镜头的录像」「录像日期与要素日期不一致」「录像缺少开始时间」。

真实浏览器验证（CASE-20261030-01，15 段 14:59–15:00 扫描，9 段匹配到 Map 镜头，锚点 18:05）：

| 场景 | 结果 |
| --- | --- |
| 添加第一个要素 | 范围自动扩为 14:54–20:05，底栏「9 段录像待分析」，作业 9 |
| 手动把范围改回 18:00–20:12 | 底栏「录像不在当前时间窗」，详情列出录像时间 14:59–15:00 与当前范围 |

截图：`.shots/plan-matched.png`、`.shots/plan-mismatch.png`。

注意：这里的「待分析」是**真实录像匹配后的作业队列**，实际读帧分析仍由「追踪任务」启动；本轮没有伪造自动分析进度。
