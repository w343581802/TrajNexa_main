# 54｜B8：M6 连续追踪正式工作台接线规划（启动版）

版本：B8-A / 2026-11-04  
代码分支：\`feat/b8-tracking-workbench\`（基于 \`ee79245\`）  
性质：**正式主系统能力的实施规划 + 首批只读结果契约**；不是宣称 M6 已接入生产。

## 1. 产品目标与默认模型决策

TrajNexa 的目标是：用户在有合法权限的案件中给定目标画面/已审核起点，系统在已有录像及空间摄像头网络中持续搜索并还原目标跨镜头路线，保留可核查证据，直至搜索结束、证据不足、资源预算耗尽或取得值得人工重点核查的清晰画面。

- **不是**只提供下一台摄像头推荐；预测、调度、实际解码/检测、候选和继续搜索要形成闭环。
- **不是**由单一大模型确认身份；OSNet 相似度、Qwen 属性、地图时空约束均是不同类型证据。
- **模型默认**：D-FINE / OSNet / **Qwen3-VL-4B**。属性抽取采用 \`large_only\`，既不隐式先跑 2B，也不把属性算进候选排序。
- **WeVisOne-VL 保留可替换插件但默认关闭**：\`default.visual_grounding=none\` 且 \`tasks.m6.one_hop.visual_grounding=none\`；研究数据、Provider 和对照实验保留，不继续本阶段专项评测。
- \`unknown\` 不等于冲突；\`visible=true\` 只代表模型声称可见，**不等于人工真值**。
- 现有三镜头记录处于 \`exploratory\`、\`pending_human_review\`、\`uncalibrated\`，不能伪装成正式生产验收。

## 3. 分阶段交付

### B8-A｜最小数据契约（本分支第一批）

- 固定默认模型配置，保留其他模型的显式选择能力。
- 新增 \`app/m6_workbench_projection.py\`：将 M6 \`m6-one-hop-chain/3\` 结果安全映射成工作台只读结构：
  \`case_id/target_id/session_state/main_chain/anchor/candidate_pool/windows/model_provenance\`。
- 强制一致的 \`case_id\`、\`target_id\`，不得把模型候选转换为 \`confirmed\`。
- 明确该适配器**没有**完成身份验证、权限、业务持久化或真实录像接入；不得直接开放“传任意 JSON 即可查看案件结果”的生产接口。
- 对已有青衣冻结结果测试：10 个弱候选与 10 个窗口原样可读，\`awaiting_review\` 状态不变。

### B8-B｜案件追踪任务与运行编排（下一批实现）

1. 增加持久化 \`TrackingRun\`、\`TrackingCandidate\`、\`TrackingReviewEvent\` 及快照/版本引用（建议通过项目现有迁移方式引入）。
2. 正式创建任务输入必须是服务器核实的案件 ID、目标 ROI / 观测 ID、只读录像段引用及地图 revision；禁止浏览器提供任意模型路径、文件绝对路径或外部 URL。
3. \`POST /api/v1/cases/{case_id}/tracking-runs\` 创建排队任务；\`GET .../tracking-runs/{run_id}\` 查询状态；\`GET .../candidates\` 读候选；\`POST .../reviews\` 记录人工决定。全部按案件隔离，需预留访问控制和审核日志；部署前必须具备认证与授权。
4. Worker 解码注册录像的实际时间段，按摄像头绑定生成窗口，调用现有 \`run_one_hop\` 和 B7 能力层。状态区分 \`queued/running/awaiting_review/budget_exhausted/unresolved/failed/completed\`。
5. 幂等任务、断点续查、任务取消、成本上限与错误码；只读原录像，不因案件删除而删录像。
6. 真实录像的 OSD 时间映射、镜头绑定及地图 revision 必须写入运行记录；\`uncalibrated\` 时不得承诺严格速度约束。

### B8-C｜工作台真实接线

- 选择案件、目标 ROI 和录像范围后启动追踪任务；界面展示任务进度、正在分析的镜头与窗口。
- 按候选状态展示 Top-K、weak、排除/已否决、来源模型、截图引用、运动和时空不确定度。
- 用户审核通过/否决后继续搜索；保留撤销、依赖失效、追踪分支历史；不能只更新内存数组。
- 地图用于展示研判路线与证据位置；\`TrajNexa_Map\` 仍仅负责地图数据编辑修正、发布，只读供主系统使用。

### B8-D｜真实端到端验收

- 从案件的真实目标素材出发，不注入真值包、不直接指定后续镜头；
- 录像、摄像头、时间窗、检测、跟踪、ReID、可选 Qwen 属性、候选展示、审核、继续搜索构成闭环；
- 原青衣回放作为基线（测试不能“提前知道 B/C”）；其他目标验证负例、遮挡及无结果。
- 含义上区分：候选时间窗命中、候选排名第一、人工跨镜头确认、自动检索闭环；不能混为一个“已确认三跳”指标。
- 完整日志和审计；数据访问需遵守授权边界，公开部署前必须补认证/权限。

## 4. 不在本轮做的事情

- 不继续做 WeVisOne 2B/4B 专项评测或提示词搜索。
- 不优化多模态融合权重，不把属性/颜色/随行状态自动应用于身份认定。
- 不把实验 \`truth_package\` 当成正式案件数据源。
- 不重建 M5 模型中心，也不要求 Qwen 取代 D-FINE / OSNet。
- 不声称目前 B8-A 已实现了 HTTP API、真实 Worker 或 Vue 接线。
