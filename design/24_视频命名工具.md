# 24_顶部工具栏：视频命名（本地路径/目录 + 开头 OCR + 重命名 + 表格）

## 需求

主系统顶栏中间放一个工具栏，第一个小工具处理录像文件名：

1. 前端是本地 demo，只传**文本路径**：一个视频文件，或一个目录；
2. 后端读取本地真实录像，不经过浏览器上传；
3. 读每个视频**真实的前几秒画面**（0.5 / 2 / 4 秒），OCR 画面角标里的**摄像头名称**和**拍摄时间**；
4. 按「摄像头名称_时间」**直接重命名原文件**；
5. 生成一份可直接交给 Excel 的**表格文件**，并保留开头截图作为证据。

## 边界

- 文件名改了、内容不动：不转码、不复制、不改文件内容。
- OCR 结果仍是**提示**：不写 Map 台账，不把角标文字当成已确认的摄像头身份；
  `needs_review=true` 表示缺名称、缺时间，或时间来自文件名兜底。
- 目录会**递归遍历子文件夹**（可关）；路径可以是宿主机路径（`G:\测试数据\视频\正常`）或容器可写路径（`/data/video-library/正常`）。
- 可选「同时重命名子文件夹」：同一子目录内视频识别为同一摄像头时，文件夹按 `摄像头名称_开始至结束` 改名；名称不一致则跳过。
- 目录扫描只处理常见视频扩展名，跳过隐藏文件；单次默认最多 200 个。
- 表格与批次记录不绑定案件；删除案件不会误删录像。
- 命名结果不依赖 CameraMap；目录不可用时只是没有台账名称可对齐。

## 链路

```
前端输入 G:\测试数据\视频\正常 或容器目录 → POST /batches {paths:[...], recursive:true, rename_folders:true}
  → API 把宿主机路径映射到 /data/video-library（可写挂载），递归展开子目录
  → 每个视频建 MediaAsset(storage_relpath=绝对路径) + AnalysisJob
  → worker 直接读本地文件：
      recordings.inspect_first_seconds() 读开头帧
      → PaddleOCR（PP-OCRv6）识别角标时间 + 名称
      → 生成 摄像头名称_YYYYMMDD_HHMMSS.ext
      → 先把证据截图写到 storage/video-tools/<batch>/frames/
      → 原地重命名原文件；数据库提交失败时 worker 把名字改回去
      → 全部完成后，按子目录共同摄像头名称重命名文件夹
  → 前端每 1.5s 轮询 GET /batches/{id}
  → 完成后下载 CSV / 重命名文件 / 查看 OCR 截图
```

复用现有 `AnalysisJob` / `InspectionReport`，不需要新表；OCR 只在带 PaddleOCR 的 worker 里跑。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/video-tools/naming/batches` | JSON：`{"paths":["G:\\测试数据\\视频\\正常"],"recursive":true,"rename_folders":true}`；路径可以是文件或目录 |
| GET | `/api/v1/video-tools/naming/batches/{batch_id}` | 批次状态、每行 OCR 结果、文件夹新旧名、截图 URL |
| GET | `/api/v1/video-tools/naming/batches/{batch_id}/table.csv` | UTF-8 BOM 的 CSV，Excel 可直接打开 |
| GET | `.../items/{media_id}/download` | 可选：下载重命名后的文件（界面已不再提供按钮） |
| GET | `.../items/{media_id}/frame` | 查看 OCR 使用的开头截图 |
| POST | `.../items/{media_id}/rename` | 人工改名：`{"name":"新文件名.mp4"}`；看截图后直接改挂载目录里的原文件 |

路径规则：

- 宿主机路径按 `VIDEO_NAMING_PATH_MAP` 映射到容器可写挂载；默认 `G:\测试数据\视频` → `/data/video-library`。
- 绝对路径直接使用；相对路径按 `VIDEO_NAMING_ROOT`（默认 `/data/video-library`）解析。
- `/data/videos` 是只读扫描挂载，命名工具写入走 `/data/video-library`（compose 中 rw 挂载）。
- 默认不限制目录（本地 demo）；设置 `VIDEO_NAMING_ROOTS`（`os.pathsep` 分隔）后只允许这些根目录。
- 单次最多 `VIDEO_NAMING_MAX_FILES`（默认 200）个视频；目录里的隐藏文件跳过。

CSV 列：序号、原始文件名、新文件名、原路径、新路径、文件夹原名、文件夹新名、摄像头名称、
拍摄时间、时间来源、OCR状态、匹配状态、时长(秒)、大小(MB)、处理状态、需人工核对、备注。

## 文件夹命名口径

勾选「同时重命名子文件夹」后，处理完整个批次再改文件夹：

`摄像头名称_YYYYMMDDHHMMSS至YYYYMMDDHHMMSS`

- 只改输入根目录**下面**的文件夹，根目录（如 `正常`）本身不动。
- 同一子文件夹内所有视频必须识别为**同一个摄像头名称**，否则整目录跳过并在日志里说明。
- 开始时间取目录内最早拍摄时间，结束时间取最晚「拍摄时间 + 时长」。
- 文件夹改名成功后，表格里的「新路径」同步指向新位置。
- 表格不再提供下载按钮（文件已在挂载目录里，直接改磁盘）；需要时用接口或文件管理器查看。

## 手动命名

OCR 没识别出来（或识别错）的行，在表格里点「手动命名」：

- 左侧显示视频开头截图（OCR 原图），右侧显示原文件名、所在文件夹、新文件名输入框；
- 底部「确定」直接重命名挂载目录里的原文件，不复制、不转码；
- 不写扩展名时沿用当前扩展名；写错扩展名会被拒绝，避免文件打不开；
- 成功后该行 `needs_review=false`，表格和 CSV 立即更新。

## 命名口径

`摄像头名称_YYYYMMDD_HHMMSS.扩展名`，例如：

`YD-桂康路中仁路T口2-2_20261023_150001.mp4`

- 名称来自角标 OCR；时间优先角标，角标缺失时才用文件名兜底，并在表格「时间来源」标明。
- OCR 名称缺失：`原名_OCR未识别_...`；时间缺失：`..._时间未识别`，并置 `需人工核对=是`。
- 文件名做 NFKC、去掉 Windows/Linux 非法字符、按 UTF-8 字节限制长度；同目录重名时追加 `_2`、`_3`。
- 扩展名保留原文件扩展名。

## 关键修复：灰占位帧被当成「已识别」

用户的原始反馈是「OCR 没有识别到有效帧就拿取截图进行识别」，截图里左侧证据画面是一整片灰色。

根因不在 OCR 模型，而在**取帧**：

- `ffmpeg` 把 `-ss` 放在 `-i` 前面是**快速 seek**，只跳到最近的关键帧；
- 30 分钟 HEVC 大文件（3200×1800 / 4096×2160）上，ffmpeg 找不到参考帧会打印
  `Could not find ref with POC 11`，**但退出码仍是 0**；
- 它输出的是一张全 `#808080` 的占位图。旧代码只看「有没有拿到 ndarray」，
  于是灰图被当成有效帧：OCR 一个字读不出、证据截图是灰的，界面却显示「已识别」。

修复三处：

1. `overlay_ocr.frame_is_blank()` 显式判定占位帧。**只用标准差不够**：实测一张 4096×2160 的
   灰图 std 恰好 6.0 卡在阈值上（只降采样/噪声稍微不同就会漏判）。主判据改成
   「众数灰阶 ±10 内的像素占比 ≥ 90%」——实测灰占位图为 96%，真实监控画面最高 40%，区分度足够；
   标准差 < 6.0 作为兜底快速返回。
2. `overlay_ocr._video_frame()` 分成 `_ffmpeg_frame(accurate=False/True)`：
   快速 seek 拿到占位帧时自动退回**精确 seek**（`-ss` 放在 `-i` 之后，从头解码到目标时刻），
   两者都是坏帧才返回 `None`。
3. `video_naming._save_evidence_frame()` 证据截图依次尝试 `0.5 / 2.0 / 4.0 / 8.0 / 15.0` 秒，
   全部失败才返回 `None`，此时不写假截图，并置 `needs_review=true`、在备注里说明。

上层口径不变：`no_frame` 会明确写进 OCR 状态列，名称/时间缺失时照常降级成
`_OCR未识别` / `_时间未识别`，绝不因为「有一帧」就宣称识别成功。

## 关键修复：名称牌没有结尾段、文件名时间带下划线

同时修掉两个漏识别（同样是「有内容却被判成没有」）：

- **名称正则过严**：`_DEVICE_CODE` 要求以 `-中文` 结尾段收尾，导致
  `YD-中仁路都市丽景正门1`、`YD-桂康路与中仁路1` 这类没有结尾段的牌子全部返回 `None`。
  新增 `_DEVICE_PLATE`：仍要求「设备前缀 + 中文地名」，但允许以数字 / 朝向 / 球 / 枪 / 机 / 门 / 口 收尾。
  整段糊掉的结果（实测 `3-DX-电仁路孔明园E40东庭街北工`）和纯场景文字（`商店招牌`）仍被拒绝。
- **文件名时间兜底漏格式**：工具自己产出的 `名称_20261023_145955.mp4` 中间多了下划线，
  而兜底正则只认连续 14 位数字，于是「二次处理后」的文件再也兜不出时间。
  正则改为允许 `[ _-]?` 单个分隔符。

## 失败与降级

- 路径不存在：404；不是视频扩展名：415；目录里没有视频：422；超过上限：422。
- OCR 未启用 / 模型不可用 / 未取到帧：仍按原名加 `_OCR未识别` / `_时间未识别` 改名，并标待核对。
- 单个文件处理失败：该行 `failed`，批次可能 `partial`；失败原因在「备注」与状态列。
- 文件夹改名仅在**整个批次全部成功**后执行；有任一失败则不改文件夹，避免半改状态。
- 文件夹内摄像头名称不一致：跳过该文件夹，文件名照常改，表格「文件夹」列留空。
- 数据库提交失败：worker 调用 `revert_rename` 把文件名改回；文件夹改名失败则把文件夹改回。
- 批次截图保存在 `storage/video-tools/<batch>/frames`，不会自动过期；部署时按需清理。
