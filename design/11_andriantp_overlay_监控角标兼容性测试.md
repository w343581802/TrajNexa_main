# TrajNexa · andriantp/overlay 监控角标兼容性与 OCR 对照测试

- 日期：2026-10-26
- 参考仓库：https://github.com/andriantp/overlay
- 使用范围：仅测试用户授权提供的两张监控截图；不包含人脸/人物识别
- 结论：不适合作为 TrajNexa MediaInspector 的即插即用替代品

## 上游真实代码的约束

1. `client.go` 将输入截取为底部 25%，只在其中搜索时间角标；两张样本的角标在右上角。
2. `internal/layout/static.go` 使用固定底部相对区域，没有上方角标布局。
3. `internal/parser/timestamp.go` 使用 `02 Jan 2006 15:04:05` 等格式，不支持本项目样本的 `YYYY-MM-DD HH:MM:SS`。使用从上游复制的 Go 标准库解析函数验证：正确时间原文依然被拒绝。
4. `client.go` 要求经纬度坐标；样本没有此类角标时，会以 `coordinate not found` 结束。
5. `internal/ocr/tesseract.go` 底层为 gosseract / Tesseract（English single-line 模式），不是专用 OSD 数字网络。

## 结论与建议

1. 不建议替换现有 PP-OCRv6。
2. 此项目可参考：字段正规化、配置角标 ROI、OCR 后严格解析；但必须改造顶部 ROI、数字日期解析、时间-only 输出和返回结构。
3. 如需真正评估修改后的 Go 版本，必须先解决 Go 依赖下载，并在同一批人工标注的监控样本上统计完整日期时间的逐字正确率、拒判率与耗时。
4. 最有意义的下一步：针对 0–9 日期数字做固定字体位置约束或视频多帧互证，而不是简单迁移此 Go 库。
