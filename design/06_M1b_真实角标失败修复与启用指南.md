# M1b 真实样本反馈：角标识别跳过与名称格式适配

## 问题根因

用户报告 `time_status=not_checked`，意味着默认 Docker Worker 因 `OCR_ENABLED=false` 跳过文字识别。原来的角标名称解析器主要接受“摄像头：”或“Camera：”等前缀，不适应一些无前缀的编码式角标。

## 本次修复

- 报告及界面区分 OCR `disabled` / `unavailable` / `error` / `ran`；未执行与执行失败不再混为一谈。
- 通过 `compose.ocr.yaml` 启动 OCR 专用 Worker 时直接配置 `OCR_ENABLED=true`，不改变默认轻量镜像。
- 只在画面底部角标带中识别带设备编码的结构化名称，作为未绑定候选，不自动认定 `camera_uuid`。
- 导出文件名中的时间范围和名称只作 `filename_unverified` 提示，与屏幕 OCR 时间、设备真实身份分开。
- 本仓库测试使用虚构样例，不提交用户上传的真实监控图像。

## 在 Windows Docker Desktop 开启 OCR

```powershell
git pull
docker compose -f compose.yaml -f compose.ocr.yaml up --build -d
docker compose -f compose.yaml -f compose.ocr.yaml logs --tail=100 worker
```

原有报告不会覆盖，请重新点击“开始媒体预检”生成新报告。首次启动 PaddleOCR 可能需要下载模型。后端单元测试通过并不等于 Docker OCR 推理及真实中文样本准确率已通过。
