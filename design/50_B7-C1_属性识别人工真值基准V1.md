# B7-C1 多模型属性识别人工真值基准 V1

日期：2026-11-04
分支：`feat/b7c-wevisone-grounding`
状态：首轮 20 裁剪诊断；**不做属性融合，不决定 WeVisOne/Qwen 的最终分工**。

## 1. 目的与边界

回答三个问题：

1. 能否准确识别衣着、车辆及随行关系；
2. 看不清时会不会编造；
3. 输出能否稳定转成 TrajNexa 需要的结构化证据。

边界：20 个裁剪只用于诊断，不用于定正式准确率；真值来自裁剪内可见内容，不参考原始视频里的“已知答案”。

## 3. 真值标注

字段：`garment_color / garment_type / vehicle_color / vehicle_type / companion_present`。

状态：

- `known`：裁剪内有足够证据；
- `unknown`：裁剪内无法判断（含“车辆在画面外”）；
- `not_applicable`：字段不适用（如行人没有骑行车辆）。

规则：

- 只看该裁剪内可见内容，不用原始视频或已知行程反推；
- person 裁剪里看不到车，车辆字段记 unknown，不记“无车”；
- 只有明确看到人物在行走/站立、无骑行车辆时，才记 not_applicable；
- 标注者为 assistant（2026-11-04 目视），**尚未经人工复核**；O02 胸前粉色物、O06 三轮类型、O09 车色是最需要复核的三处。

## 4. 实验设置

| 项 | WeVisOne-VL-2B | Qwen3-VL-4B |
| --- | --- | --- |
| 权重/量化 | tencent/WeVisOne-VL-2B（4.88 GB） | qwen3-vl:4b-instruct（q4_K_M, 3.3 GB） |
| 设备 | 本机 CPU，bf16 | RTX 3060 Laptop 6 GB，Ollama |
| 提示 A（结构化） | 只输出 JSON，五字段，看不清 unknown | 同左 |
| 提示 B（自然语言） | 一句话描述衣着/车辆/同行 | 同左 |
| 提示 C（caption） | `describe the image with bounding boxes in detail`（task=freeform） | — |

WeVisOne 官方引擎的 `TASKS` 没有 `caption`；demo 的 Caption 入口是把预设句当 `freeform` 的 query 传入，本轮按同样方式调用。

解析：保留 WeVisOne 的 `<ref>…</ref><box>…</box>` 原文，用 ref 文本还原语义；颜色按族归一（light blue→blue、dark green→green），衣类按 outerwear/shirt/t_shirt 归并。所有归一规则只用于评分，不改变原始输出。

## 5. 结果

### 5.1 结构化可用性

| 指标 | WeVisOne-2B（自由问答） | WeVisOne-2B（caption） | Qwen3-VL-4B |
| --- | --- | --- | --- |
| JSON 合规 | **0/20** | — | **20/20** |
| 可读文本 | 0/20（输出是提示词短语的 ref/box，无答案） | 20/20（有英文描述） | 20/20 |
| 平均耗时 | 16.0 s（CPU） | 14.1 s（CPU） | 2.0 s（GPU，JSON） |

### 5.2 字段准确率（all / person / context）

| 字段 | Qwen JSON all | person | context | WeVisOne caption all |
| --- | --- | --- | --- | --- |
| garment_color | **0.833** | 0.889 | 0.778 | 0.333 |
| garment_type | 0.556 | 0.667 | 0.444 | 0.056 |

WeVisOne 自由问答在 20 个裁剪上没有任何字段级输出，准确率记 0（无法评分，不是“答错”）。

## 6. 发现

1. **Qwen 能稳定给结构，但不守 unknown 纪律**。O03 两个裁剪都不可辨认，Qwen 仍输出 garment_color=purple；O01/O02 的同伴在裁剪内无法判断，Qwen 一律回答 no。结构化输出掩盖了“它在猜”。
2. **WeVisOne 的 freeform 不是问答**。给它“只输出 JSON”或“用一句话描述”，它会把提示词里的每个短语当作指代目标逐一框出（例如 `<ref>穿什么颜色的衣服</ref><box>…`），不产生答案；20/20 如此。它的 caption 模式才有可读文本。
3. **WeVisOne caption 的车辆类型可用，颜色/衣着不可用**：vehicle_type 0.929，但 garment_color 0.333、garment_type 0.056、vehicle_color 0.067；很多物体只以 ref 形式出现，不写属性。
4. **裁剪范围显著影响分数**：person 裁剪看不到车，Qwen 的 vehicle_color 从 context 的 0.375 掉到 0.286；但这不能算“识别差”，是输入不足。必须分列 person/context（本表已分）。
5. **幻觉有具体案例**：O07 是站立看手机的行人，Qwen 给出 red motorcycle / white cover / yellow scooter；WeVisOne caption 给出 “indoor scene, holding a bowl”。两者在“无车/无同伴”场景都会补出不存在的东西。
6. **速度不可比**：Qwen 2.0 s 是 GPU + 4bit，WeVisOne 16 s 是 CPU + bf16；要比较成本必须在同一硬件重测。
7. **衣类与车色是共同弱项**：Qwen 衣类 0.556、车色 0.333；WeVisOne caption 衣类 0.056、车色 0.067。两模型在这两个字段上都不足以上生产。

## 7. 局限

- N=20，只够诊断，不够定准确率；
- 真值为 assistant 标注，未经人工复核；
- 文本指标用关键词启发式解析，中文/英文混合时可能低估；
- 颜色按族归一，会掩盖“浅蓝 vs 蓝”这类细节差异；
- 只测了一个提示词版本，未做提示词搜索。

## 8. 结论与下一步

- 本轮**不能**得出“Qwen 属性更好”或“WeVisOne 只适合定位”的结论：
  Qwen 胜在结构化与部分字段（衣色、同伴、车类），输在 unknown 纪律与车色/衣类；
  WeVisOne 胜在车类，自由问答完全不可用，caption 可作为弱证据来源。
- 继续不做属性融合，不固定分工。
- 下一步（若继续）：人工复核 20 条真值 → 扩到 50 个独立观测 → 固定 JSON/文本解析器 → 再决定是否融合。
