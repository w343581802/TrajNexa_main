# B8 时间轴 V1.2（区域研判修订）实施计划

> 来源：用户提供的《B8 时间轴、地图统一证据与区域研判联动实施规划 V1.2（区域研判修订版）》与《B8-S V1.2.1（时间轴对齐修订版）附录》。
> 本文只做排期与勾选，不改两份文档的结论；技术路线、L0–L3 分层、SA0–SA6 与 G0–G4 闸门维持不变。

## 1. 本次修订的实质

时间轴从「技术对象驱动」改为「目标追踪进展驱动」：

| 原设计（design/67 批次 1） | 修订后 |
|---|---|
| 起始锚点作为一级卡片 | 起始目标证据：未关联有效轨迹时作为入口，关联成功后收进轨迹详情 |
| 追踪任务按摄像头拆卡 | 正在研判区域大卡：一张卡聚合多台设备/窗口，按计划录像时间插入主时间轴 |
| 候选轨迹逐条占位 | 待核查轨迹：同镜头同时段候选先汇总，展开成候选分支 |
| 人工确认的候选直接成卡 | 已确认轨迹：需真实逐帧连续段，身份与空间质量分别标注 |
| 证据缺口逐条成卡 | 轨迹中断说明，作为相邻段之间的提示 |
| 研判日志占一块版面 | 默认折叠，保留完整执行记录 |

关键工程约束（本次新增、必须体现）：

1. **区域卡不代表目标到达该区域**；只表示“正在检查这些摄像头”。
2. **两类延长时间语义不同**：`继续研判 +60s` 增加 Worker 执行预算（`research_seconds`）；`扩大录像检索范围 +N 分钟` 增加录像事件时间窗（新计划窗口）。二者不可互相冒充。
3. 当前 `/extend` 只更新预算字段，Worker 是否消费尚未验证，界面不得显示“已继续分析录像”。
4. `TrackingCandidate` 只有窗口与轨迹 ID，**不等于**有首末帧和断点的 `TrackSegment`；无逐帧数据时显示“候选线索（尚未生成连续段）”，不编造段数/点数/起止帧。
5. 身份已确认 ≠ 地理位置已验证；区域研判、候选轨迹、实验估计均不得自动升级为正式 L2/L3。

## 2. 现状核对（2026-11-06）

已完成（有代码与运行证据，不重做）：

- 时间轴只读读模型与事件流：`backend/app/timeline_projection.py`、`timeline_api.py`（58 张卡、事件按 `created_at` 派生、不落表）。
- 卡片唯一选中 `selectedCardId`，按案件记忆，刷新恢复；地图与时间轴双向高亮（`track_id` 同源才高亮）。
- 卡片回看：代理片段（H.264 重编码）+ 关键帧证据 + 帧框叠加。
- 显示闸门：`b8_gates.py` 三开关，关闭时 404 `experimental_geo_display_disabled`。
- TB4 目标绑定实验层（33 帧样本，`persisted=false`），与正式 L2 隔离由测试保证。

未实现（本计划的靶子）：

- 三态主筛选（已确认轨迹／待核查轨迹／正在研判区域），当前仍是按 `kind` 的技术分类。
- 区域研判大卡（聚合多设备、计划录像时间范围、完成窗口、失败原因、派生卡片关联）。
- 两类延长时间的分离与“预算已增加／已续跑”的真实回执。
- 真实 Run 的逐帧段（B2-1/B2-2 卡住的原因）。
- 地图区域选中只高亮设备/FOV/检索范围（当前只做了轨迹段联动）。

## 3. 实施原则

1. 读模型不造事实：区域卡、三态、派生卡片全部从既有 `TrackingRun/Window/Candidate/Observation/ReviewEvent` 派生；没有计划就显示“待规划”。
2. 不猜设备：设备清单只来自真实窗口记录，不按距离/名称补造排队摄像头。
3. 时间两套：`observed_*`（录像事件时间）与 `analysis_*`（Worker 执行时间）严格分开，区域卡按计划录像时间插入。
4. 身份与空间正交：任何卡片不得因位置合理而升级身份，也不得因身份确认而升级空间等级。
5. 如实降级：无录像、无逐帧、时钟未核验、标定失效都要有明确文案，不生成伪路径。
6. 每项勾选需代码 + 测试 + 真实运行证据三件齐。

## 6. 明确不做的事

1. 不为区域卡新建事实表；区域阶段是读模型聚合。
2. 不把区域覆盖当目标到达证据，不画“目标经过区域中心”。
3. 不用 TB4 试点样本充当真实 Run 证据。
4. 不在本轮改 TrajNexa_Map 端点（B0-3 仍需单独授权）。
5. 不以“能画出线”作为精度验收；无独立真值就停在 `experimental_estimate`。
